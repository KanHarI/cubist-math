        Language quick reference
        
      
          Full language reference →
          — syntax, worked examples, paths, universes, and axiom signatures.
        
      
        
      
          def name(params) := term; defines a term with an inferred
          type. def name(params) : T { … } checks a proof of
          T. Use def for both constructions and proofs.
          Parameters have explicit types; consecutive ones may share a type, as in
          (A, B : U0, x, y : A). Imports come first: import paths;.
          Comments start with //.
        
      
        
      
          // comments immediately above a declaration become its
          inspector description. An empty // line separates paragraphs;
          a blank source line separates a section comment from a declaration.
        
      
        
      
          U0, U1, U2 and U3
          name universes, with U0 : U1. A parameter
          U : Universe accepts a universe argument.
          Inspect a template and select U0–U3 to see its checked specialization.
          Equiv(U, A, B) and IsEquiv(U, A, B, f)
          work at that universe. Choice(U0), LEM(U0)
          (excluded middle) and Truncate(U1) specialize the library
          assumptions to a universe.
          ua(U, A, B, e) turns an equivalence into a path of types, and
          UnivalenceBeta computes transport along it. Like
          FunExt(U, A, B, f, g, h), they are constructions, not assumptions.
        
      
        
      
          x =[T] y means equality of x and
          y as elements of T; plain x = y
          infers that carrier. In particular, A =[U] B is equality
          of types A : U and B : U in universe
          U.
        
      
        
      
          refl(x) proves x = x, and any x = y
          whose sides compute to the same value. The built-in
          sym(p) reverses
          p : x =[T] y to give y =[T] x;
          trans(p, q) joins paths x = y and
          y = z; cong(f, p) gives
          f(x) = f(y). These are checked path operations,
          with no additional axioms. See equality and paths.
        
      
        
      
          intro name; (or intro x, y, h; for several) introduces the next input or assumption from
          the current goal. For forall x : A. B, it names an input
          of type A; for P -> Q, it names evidence of
          P and leaves Q to prove. The type comes from
          the goal, including when the goal is a named definition.
        
      
        
      import sets;
def use_assumption : forall A : U0. IsSet(A) -> IsSet(A) {
  intro A;       // A : U0
  intro setA;    // setA : IsSet(A)
  exact setA;
}
      
        
      
          Here IsSet is defined in the sets module:
          equality proofs between the same two elements agree. Click an
          introduced name to see its type, or a line number to inspect the goal
          and local assumptions.
        
      
        
      
          let names a term · obtain unpacks an
          existential or pair · have h : T { … } proves a local claim ·
          have h := term; names an inferred proof ·
          have h : T := term; checks and names one ·
          cases splits an or ·
          exact supplies the result ·
          absurd eliminates a contradiction.
        
      
        
      
          Types use forall x : A. B, exists x : A. B,
          and, or, and ->. Natural-number
          expressions use +, *, =,
          <, and <=.
        
      
        
      
          With import binary_naturals;, 0b110 denotes
          six in BinaryNat, using one W constructor per bit.
          Hover to see its constructor expansion. Decimal literals such as
          6 remain unary Nat; conversion is explicit.
        
      
        
      
          W(A, B) forms well-founded trees with labels in
          A and children indexed by B(label).
          sup(T, label, children) builds a tree;
          wrec(T, motive, step, tree) performs dependent induction.
          See W types and binary numbers.
        
      
        
      
          forall is a dependent function (Π); exists
          is a dependent pair (Σ) with an actual witness. A and B
          is a product; A or B is a disjoint sum, displayed as
          A + B in kernel notation. Mere existence requires
          truncation; exists does not truncate automatically.
        
      
        
      def identity(A : U0, x : A) := x;
def pair := typed(Nat and Nat, (0, 1));
def either := typed(Unit or Nat, left(tt));
def pair_first : Nat {
  obtain (a, b) := pair;
  have result : Nat { exact a; }
  exact result;
}
      
        
      
          fun (x : A) => body constructs a function;
          fun (x, y : A) => body and fun (a : A, b : B) => body
          take several arguments, and fun x => body reads the domain from
          an expected function type. f(a, b) means f(a)(b).
          (a, b, c, d) expands to (a, (b, (c, d)));
          obtain (a, b, c, d) := value; unpacks that same shape.
          Hover over tuple parentheses to see the macro expansion.
          typed(T, term) supplies an expected type for pairs and
          injections. exact, cases, rfl,
          calc, simpa and over finish a block;
          no further statements follow them in that block.
        
      
        
      
          import primes; checks the mathematical source of the
          arithmetic library.
          induction n as k return C { zero => base; succ ih => step; }
          handles natural-number induction. match and
          unpack
          handle case analysis and pairs. Click notation or a numeral to inspect
          its meaning. The kernel audit entries retain the complete original
          instruction histories.
        
      
        
      
          In induction n as k return C(k), the zero branch proves
          C(0). The successor branch has predecessor
          k : Nat and hypothesis ih : C(k), and proves
          C(succ(k)). For a result depending on a whole pair, use
          pair_induction(motive, branch, pair).
        
      
        
      
          transport(C, x, y, p, value)
          moves value : C(x) along p : x = y into
          C(y); along C by p from value is the same with
          the endpoints read from p.
        
      
        
      
          Equational reasoning.
          rfl; closes an equality whose sides compute to the same value.
          calc { a = b by p; _ = c by q; } chains steps; _
          is the previous right side, and a step may be proved by a nested
          by { … } block.
          rw [p, <- q] at lhs occurrence 2; rewrites with
          instantiated equalities such as nat_add_zero(n), in order;
          <- rewrites right to left, and occurrences count
          left side then right. If the new goal holds by computation, rw
          closes the block; otherwise a following statement proves it.
        
      
        
      import primes;
def add_zero_twice(n : Nat) : (n + 0) + 0 = n {
  calc {
    (n + 0) + 0 = n + 0 by nat_add_zero(n + 0);
    _ = n by nat_add_zero(n);
  }
}
def rewrite_then_finish(n, m : Nat, h : n = m) : n + 0 = m {
  rw [nat_add_zero(n)];   // goal: n = m
  exact h;
}
      
        
      
          Simplification.
          simp only [nat_add_zero]; rewrites with the listed rules
          everywhere, repeatedly, inferring quantified arguments by matching.
          simpa only [rules] using h; simplifies both the goal and
          the type of h, then uses h. On a goal that is a type,
          such as P(n + 0), simp rewrites the type and
          transports the proof back. Top-level simp_rule lemma priority 10;
          registers a default rule and simp_set units := [lemma]; names a set;
          both carry through imports. Then simp; uses the defaults,
          simp [units]; adds to them, simp without [lemma];
          drops one, simp [units] at h as h2; adds a simplified copy of
          h, and simp with [h]; supplies a premise for a
          conditional rule. Cycles such as commutativity are rejected; instantiate
          them instead. Prefer simp only in library proofs; click a
          simp to see its trace or replace it with the equivalent
          simp only list. See
          equational reasoning and
          simplification.
        
      
        
      
          Cubical paths.
          path(fun (i : Interval) => A, fun (i : Interval) => body)
          constructs a path, and at(p, i) evaluates it at a coordinate.
          Where a path type is expected, path i => body reads the family
          from it, and p @ i abbreviates at(p, i).
          ext x; reduces f = g to f(x) = g(x)
          without an axiom. apd_path(f, p) is the dependent path of a
          dependent function over p, and
          over C along p by { … } proves a PathP goal from an
          equality after transport.
          Pushout(S, A, B, f, g) glues along the two maps.
          Suspension, north, south, and meridian
          are ordinary definitions from import suspension_types;.
          See cubical paths and pushouts and the
          checked examples.
        
      
        
      
          Named definitions have checked bodies that the checker can unfold.
          Conversion unfolds them as it needs them. In the native cubical backend,
          with unfolding [alias, another_alias] { expression } suggests which
          checked definitions to unfold while elaborating the enclosed expression.
          The compiler can retain a checked helper for this block so the enclosing
          proof can reuse it without expanding it again.
          It does not assume an equality or normalize the whole proof.
          There is no axiom declaration: a source file cannot add assumptions.
          Truncation, choice and excluded middle are the explicit library assumptions; see
          their signatures and restrictions.
          Function extensionality and univalence compute; see
          extensionality and univalence.
          computable def requires a declaration to use no assumption, and
          evaluate term expecting value; checks what a closed term computes to;
          see computability.
