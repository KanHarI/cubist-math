SYNTAX, MEANING, AND CHECKED EVIDENCE

Language reference

Write terms and proofs in dependent type theory. Cubist elaborates each declaration into instructions checked by the C kernel.

The reference describes the mathematical .cubist language in the chapters below. The test suite checks every complete example, including the rejected ones and their error messages. The few partial sketches are marked as such in the page source.

One principle runs through the whole language. The elaborator is written in JavaScript and may be arbitrarily clever: it expands notation, finds rewrite positions and chooses simplification rules. It is not trusted. Everything it produces is an ordinary kernel term, and the C kernel checks every one of them. A convenience that the kernel cannot check makes the declaration fail. It never becomes an assumption.

Using Cubist

  • In the browser: write and check proofs in the proof workspace. Chapter 11 explains editing, checking and the inspector, and the workspace’s quick reference summarizes the syntax.
  • From the command line: node cli/repl.mjs check FILE.cubist checks a file with the same kernel. See the command-line checker and the CLI guide for setup and commands.
  • In the REPL: try terms and declarations one at a time, each checked by the kernel: on the REPL page, in the console under every proof in the workspace, where the proof’s names are loaded, or in the REPL bar at the bottom of these pages. let x := 7; defines, typeof x; shows a type and evaluate x; a value.
  • Kernel terms: the kernel workbench shows checked terms, their context, reductions, the kernel’s abstract syntax tree of native nodes, and the judgement graph it derives. The kernel reference, still to be written, will describe the kernel and its opcodes.
  • New to Cubist: start with chapter 1, types and values, then a first proof. Every example in this reference is checked by the test suite; incorrect examples show their error message as a // Error: comment.
  • Inspect any example: examples are also checked in your browser as you read. Click a name in one to see its checked kernel term, type and context, in the same inspector as the proof workspace; Open in workspace lets you edit and run it.

Chapters

  1. Types and valuesThe basic types and their values: numbers, Unit and Void, pairs, alternatives, functions, types themselves, and forall and exists.
  2. A first proof and filesWrite a first proof, then learn how a source file is laid out: imports, names, comments and declarations.
  3. Terms, functions and pairsThe basic types and the terms that build and use them: functions, pairs, sums, Unit and Void, and numbers.
  4. Proof blocksA proof block builds a term one statement at a time. Each statement extends the context, changes the goal, or closes it.
  5. UniversesTypes of types, and declarations that work at every universe.
  6. Natural numbers and inductive typesInduction on natural numbers, well-founded trees, and binary numerals.
  7. Equality and pathsIdentity types, their basic operations, and path induction.
  8. Equational reasoning and simplificationChains of equalities, rewriting with checked lemmas, and simplification.
  9. Cubical paths, pushouts and suspensionsPaths as functions of an interval, dependent paths, composition, and the higher inductive types built in today.
  10. Conversion and unfoldingWhen two terms are equal by computation, and how definitions unfold.
  11. Assumptions and computabilityThe explicit library assumptions, and how a result states and checks that it computes.
  12. Checking and inspectionWhere to check a proof, and how to read what the checker found.
  13. Error messagesEvery error message shown in this reference, what it means, and what to do.

Library examples

  • Euclid: introductions, local claims, pair witnesses, and sum cases.
  • Paths: identity induction, symmetry, composition, congruence, path i => and apd_path.
  • Primes: natural-number induction with cong, sym and trans, and calc chains.
  • Ring laws and ordered fields: simp only and simpa only on algebraic identities.
  • Group operations: chains of rw.
  • Field extensionality: pair paths built with over.
  • Right inverses of surjections: set assumptions, choice, and mere existence.
  • The circle’s fundamental group: suspension paths, equivalences, and univalence.
  • Complete ordered field interface: explicit universes and constructive hypotheses.

For the exact accepted grammar and elaboration, see parser.mjs and cubical-elaborator.mjs. Library definitions are ordinary checked source; their signatures remain the authority for their particular arguments and universes.
