A first proof

def identity : forall A : U0, A -> A {
  intro A;       // A : U0
  intro value;   // value : A
  exact value;
}

A theorem proves its stated type by constructing a term of that type. Here the statement forall A : U0, A -> A says: for every type A, there is a function from A to A. The proof constructs that function. No axioms or imports are needed.

At every point in a proof block there is a goal, the type still to be proved, and a context, the names available and their types. At the start the goal is the whole statement and the context is empty.

  • intro A; takes the first input from the goal and adds it to the context. The goal becomes A -> A and the context holds A : U0.
  • intro value; does the same again. The goal becomes A and the context also holds value : A.
  • exact value; supplies a term of exactly the goal type and finishes the proof.

In the proof workspace, click a proof-step line number to see its goal and context.

The same proof as a term

A proof block is a readable way to build a term. The same function can be written directly:

def identity(A : U0, value : A) = value;

def identity_on_numbers = identity(Nat);

def five = identity(Nat, 5);

Both forms produce the same kind of kernel term: a function taking a type and an element of it. The second identity is used twice: identity(Nat) is the identity function on Nat, and identity(Nat, 5) is the number 5. Chapter 3, proof blocks, describes every statement a block can contain.

A wrong proof is rejected with a message, and nothing is added. Here the last step offers the type A where an element of A is needed:

def not_identity : forall A : U0, A -> A {
  intro A;
  intro value;
  exact A;
}

What checking means

Cubist has two parts. The elaborator, written in JavaScript, reads source and builds kernel terms. It expands notation, finds rewrite positions and chooses simplification rules. It is not trusted. The kernel, written in C, checks every term the elaborator produces. A declaration is accepted only when the kernel accepts its term at its stated type.

A convenience that the kernel cannot check makes the declaration fail. It never turns into an assumption. The only assumptions are the explicit library ones described in chapter 10, assumptions and computability, and each theorem lists the ones it uses.

Each declaration is checked on its own. A rejected declaration is not added, so a later declaration that uses it fails too, with a message naming the missing dependency:

def wrong : Nat {
  exact tt;
}

def uses_wrong = succ(wrong);

Here wrong fails with “Type mismatch.”, because tt is not a number, and uses_wrong fails because wrong does not exist. Chapter 11, checking and inspection, shows where to run the checker and how to read its results.

Files and imports

A source file has the extension .cubist. It starts with imports, followed by declarations and directives in any order:

import primes;
import sets;

// Declarations and directives follow the imports.
def four = 2 + 2;

An import names a module without quotes or a file extension. import primes; loads primes.cubist. The command-line checker looks first in the directory of the file being checked, then in the library. The imported module is checked too, along with everything it imports.

An import makes every checked declaration of the module available, and so do the modules it imports in turn. It also brings the simplification rules and sets that those modules register. Importing a module does not make a theorem depend on that module’s assumptions. Each theorem’s assumptions are computed from its own checked term.

Imports must come first. An import after a declaration is a syntax error:

def zero_again = 0;

import primes;

Names and comments

A name starts with a letter or an underscore, followed by letters, digits and underscores. Names are case-sensitive: value and Value are different names.

def value = 0;

def Value = 1;

def value_is_zero : value = 0 {
  exact refl(0);
}

Comments run from // to the end of the line. There are no block comments and no string literals. Source is plain ASCII: write ->, forall and exists, not arrows or quantifier symbols. The inspector can display mathematical symbols, but the source cannot contain them:

def arrow(A : U0) : A → A {
  intro a;
  exact a;
}

A name cannot start with a digit:

def 2nd = 0;

Descriptions

// comments directly above a declaration become its description in the inspector, including when the declaration is imported. Consecutive comment lines join into one paragraph, and an empty // line starts another. A blank line separates a section comment from the declaration that follows it. A comment at the end of a line does not describe the next declaration. Descriptions are plain text and do not affect checking.

// Section: successors.

// The successor of a number.
//
// A second paragraph of the same description.
def next(n : Nat) = succ(n);

Here the first comment is a section comment, because a blank line follows it. The next three lines are the description of next.

Declarations

A declaration names a checked term. There are two main forms:

FormMeaning
def name(params) = term;The term form. The result type is inferred from the term. The parameters are optional.
def name(params) : T { … }The block form. The block is checked against the stated result type T. Use it for proofs and for constructions whose type should be stated.
 
def identity_term(A : U0, x : A) = x;

def same(A : U0, x : A) : A {
  exact x;
}

def self_equal(A : U0, x : A) : x = x {
  exact refl(x);
}

A term declaration ends with ;. A block declaration ends with }. There is no form with both a stated type and a term: in def four : Nat = 4; the checker reads Nat = 4 as the type, an equation, and then expects a block:

def four : Nat = 4;

To state the type of a short term, use a block with exact, or typed:

def four : Nat {
  exact 4;
}

def also_four = typed(Nat, 4);

A missing semicolon is reported at the next token:

def one = 1
def two = 2;

Other declaration forms

FormMeaning
opaque def name …Accepted, and currently checked and unfolded like def. See conversion and opacity.
computable def name …A definition that must use no assumption. See computability.
evaluate term expecting value;A directive that checks what a closed term computes to. See evaluate.
simp_rule name priority N;
simp_set name = [rule, …];		Directives that register checked equalities for simplification. See registering rules.
axiom name(params) : T;Parsed, but always rejected. See below.

A source file cannot introduce its own assumptions. axiom declarations are parsed and then rejected, and declarations that use them are blocked. The available assumptions are the library’s fixed schemas, such as truncation and excluded middle, described in assumptions.

axiom Oracle : Nat -> Nat;

def ask = Oracle(3);

Parameters

A parameter list is a comma-separated sequence of typed binders. Consecutive parameters with the same type may share it: (A B : U0, x y : A) means (A : U0, B : U0, x : A, y : A). A later parameter’s type can mention earlier parameters, as x : A does.

def flip_arguments(A B C : U0, f : A -> B -> C) : B -> A -> C {
  intro b a;
  exact f(a, b);
}

def pick_second(A B : U0, x y : A, b : B) = y;

def picked = pick_second(Nat, Unit, 1, 2, tt);

A declaration with parameters is a function of them. Every argument is written at each use: there are no implicit arguments, so pick_second takes the types Nat and Unit explicitly. Arguments can also be supplied a few at a time:

def pair_up(A B : U0, a : A, b : B) : A and B {
  exact (a, b);
}

def with_zero = pair_up(Nat, Unit, 0);

def completed = with_zero(tt);

with_zero has type Unit -> Nat and Unit. Supplying more arguments than a function takes is an error:

def pick_first(A B : U0, a : A, b : B) = a;

def too_many = pick_first(Nat, Nat, 1, 2, 3);

Every parameter needs a type. After x, the parser expects either another name sharing the type or a colon:

def untyped_parameter(x) = x;

Parameters or a quantified type

A statement can put its inputs in the parameters or in the result type. These two declarations have the same type, forall A : U0, A -> A:

def in_parameters(A : U0, a : A) : A {
  exact a;
}

def in_type : forall A : U0, A -> A {
  intro A a;
  exact a;
}

Parameters are shorter. A quantified result type is better when the statement is a named proposition that other declarations reuse.

Order, scope and recursion

Declarations become available in source order. A declaration can use only the declarations above it and the imported ones. There are no forward declarations:

def uses_later = later;

def later = 0;

A declaration cannot refer to itself, so there is no recursive definition. Recursion and induction use an eliminator instead, such as natural-number induction:

def loop(n : Nat) : Nat {
  exact loop(n);
}

Each name can be declared once in a module:

def twice_named = 0;

def twice_named = 1;

Inside a declaration, parameters and local names shadow outer ones. Choose fresh local names when a clash would be confusing to the reader.
