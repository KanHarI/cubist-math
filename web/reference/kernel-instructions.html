How an instruction works

An instruction is one C function, cc_instr_… in kernel/include/cubical_kernel.h. It takes earlier judgements and context entries by their numbers, and operands such as a level, a symbol, a face formula or a step rule; it checks its side conditions; and it publishes one judgement, or records an error and publishes nothing. Every side condition on a term is checked by syntactic equality up to bound names, on a term the instruction received or built by substitution or restriction; nothing is reduced or unfolded unless the instruction is Step and names the rule. An instruction does nothing while an error is recorded; cc_kernel_clear_error clears it.

The judgement's context is derived from the premises' contexts by merging, discharging and binding, as chapter 14 describes, and the result is published with the instruction's record for the derivation graph. In the tables below, Γ ⊢ t : T stands for a typing judgement given as a premise, ≡ for an equality judgement, and ≡α for the syntactic check. An instruction's result context is the union of its premises' contexts, less what it discharges, unless the table says otherwise.

Context entries

Three functions make entries rather than judgements, and return the entry's number.

  • Extend(type, symbol) makes the term entry x : A from a typing judgement Γ ⊢ A : U(ℓ) and a nonzero symbol. If the symbol already names an entry, that entry is returned when it is a term entry with the same source judgement or an equal type, and the call is refused otherwise. The entry's scope is Γ together with itself.
  • Level(symbol) makes the level entry x < ω, whose type is the bound LBound(1); an existing level entry of that symbol is returned, and a term entry's symbol is refused.
  • Dimension(index) returns the one dimension entry of an index below 64.

A face entry is made only by Restrict, below.

A universe-generic declaration (chapter 6) is a LevelLambda whose type is a LevelPi; using it at U2 is a LevelApply at the level 2. A level variable ranges over the natural numbers only, so LevelApply refuses ω, the level of UU0.

Functions and pairs

InstructionPremises and checksPublishes

Pair(T, a, b)Γ₁ ⊢ Σ (x : A). B : U(ℓ), Γ₂ ⊢ a : A' with A' ≡α A, and Γ₃ ⊢ b : B' with B' ≡α B[a/x]Γ₁ ∪ Γ₂ ∪ Γ₃ ⊢ (a, b) : Σ (x : A). B, the pair carrying its type

Domain and Family recover the parts of a type former as types in its universe, which cumulativity allows; the elaborator uses them to type a binder from a function type it already has. The type of a function is the Π type as written, so Apply compares the argument's type with the domain by syntax: an argument whose type is equal only by computation must first be converted (below).

A motive is checked as a function type into a universe whose domain is the eliminated type, and a case's type is compared, up to bound names, with the type the motive gives it. The natural numbers are not here: UNat is a declared type, and induction on it is its eliminator.

Paths

InstructionPremises and checksPublishes
Path(i, A, l, r)a dimension entry i, Γ₁, i ⊢ A : U(ℓ), Γ₂ ⊢ l : A[0/i] and Γ₃ ⊢ r : A[1/i], the endpoint types up to syntax; i is bound in AΓ₁ ∪ Γ₂ ∪ Γ₃ ⊢ Path(i. A, l, r) : U(ℓ)

PathAt(p, r)Γ ⊢ p : Path(i. A, l, r) and an interval expression rΓ, Δ ⊢ p @ r : A[r/i], Δ the dimension entries r uses, annotated as above

Note what PathApply does not do: p @ 0 is published at the type A[0/i], not l. That p @ 0 equals l is a Step with the path rule, which reads the endpoint from the annotation (chapter 17). The annotation is what makes this possible when p is a variable, and it is why chapter 15 describes it as the instructions' addition to the syntax.

Composition systems

A composition comp^i A [φ ↦ u] a₀ : A[1/i] is built one tube at a time, as a system judgement (kind 3) that holds the composition so far as its term and A[1/i] as its type, together with a pending set of earlier tubes the latest tube overlaps and has not yet been shown to agree with.

InstructionPremises and checksPublishes
System(i, A, a₀)a dimension entry i, Γ₁ ⊢ A : U(ℓ) and Γ₂ ⊢ a₀ : A' with A' ≡α A[0/i]; a₀ must not use ithe system comp^i A [] a₀, with nothing pending
SystemTube(s, φ, u, e)a system with nothing pending; a face formula of at most one clause. On the face 0, any typing judgement u and no equality: the tube is never used. On a clause φ: it is consistent and does not mention i; u mentions none of its dimensions (it is already restricted); u : A|φ; and the equality e is u[0/i] ≡ a₀|φ, both sides up to syntax. Face entries that φ implies are discharged from u's and e's contextsthe system with the tube appended, and pending every earlier tube whose face is compatible with φ; a compatible tube at position 64 or above is a resource refusal
SystemOverlap(s, n, e)the system's latest tube overlaps the tube at position n; e is u|ψ ≡ v|ψ on the conjunction ψ of the two faces, up to syntax, with the face entries ψ implies dischargedthe system with position n no longer pending; also used for a Glue term's tubes
Comp(s)a system with nothing pending; i is dischargedΓ ⊢ comp^i A [φ ↦ u] a₀ : A[1/i]
HComp(s)as Comp, and A does not use i and its weak head is an instance of an admitted higher declared typeΓ ⊢ hcomp^i A [φ ↦ u] a₀ : A
Trans(s, φ)as Comp, with A's weak head an instance of a higher declared type, and the system's tubes exactly the clauses of φ in order, each tube's term a₀ restricted to its clause, up to syntaxΓ, Δ ⊢ transp^i A φ a₀ : A[1/i], Δ the dimensions φ uses

The source-level comp(family, base, walls…) (chapter 11) is a System, one SystemTube per wall with the agreement equalities the elaborator derives, the SystemOverlaps where walls meet, and a Comp. A wall written on a face of several clauses is split by the elaborator into one tube per clause. HComp and Trans close the same kind of system into the formal operations of a higher inductive type; an ordinary data type, one with no path constructor and no truncation, has neither, and composes by Comp, which computes on its constructors (chapter 17).

A Glue type Glue [φ ↦ (T, e)] A and a Glue term are built the same way as a composition, piece by piece, as system judgements.

Equiv(A, B) is Σ (f : A → B). Π (y : B). IsContr(Fiber(f, y)) with Fiber(f, y) = Σ (x : A). Path(B, y, f(x)) and IsContr(F) = Σ (c : F). Π (p : F). Path(F, c, p): a function whose fibers are contractible, as the library's contractible_maps defines it. No equivalence is primitive; univalence is built from these instructions.

Declared types

An inductive declaration (chapter 8) is admitted as a signature, one constructor at a time, from judgements derived by the ordinary instructions in a context of the signature's own entries. The kernel checks that each constructor type has the normal form the H1 specification requires, as written: data arguments, then recursive positions, then a result that is the sort or an iterated path type over it with boundaries built from earlier constructors and positions.

The H1 specification states the normal form and the elimination rules in full; induction and match on a declared type elaborate to Eliminator, one EliminatorClause per clause and EliminatorClose, applied to the scrutinee with Apply.

A step on a typing judgement's term is subject reduction; on its type, it keeps a type. To derive t ≡ t' : A from t : A, the driver takes Refl and then steps on side 1. Everything chapter 5 calls computation happens through these two instructions, each naming the position and the rule, so a derivation records exactly which redexes were contracted to accept a declaration, and nothing is contracted that the derivation does not show.

import unat;
use unat;

def one_plus_one : 1 + 1 = 2 { rfl; }

The Elaboration panel shows the derivation: the numerals and add are built with ConIntro, PiElim and DefLookup, the path type with DimExt and PathForm, and the constant path with PathIntro. Then Delta, Beta and Iota steps rewrite the path's type, and Eta and HighSubs the ascription's domain, each at a stated position, until the two meet by syntax, and the ascription is applied with PiElim.

Retired instructions

Eleven opcodes remain in cc_instruction so that the numbers stay stable, and have no C entry point: the primitive natural numbers (2 to 5), pushouts (44 to 47) and W types (48 to 50). Each of those types is now a declaration in the library, admitted through the declared-type instructions like any other.
