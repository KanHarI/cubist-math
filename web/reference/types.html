Introduction

Cubist is a language for writing mathematics that a computer checks. A Cubist file defines objects, states theorems about them, and proves each theorem. The checker accepts a declaration only when its proof really proves its statement.

Every value in Cubist has a type. A statement is a type too, and a proof of the statement is a value of that type: proving a statement means building a value of the right type. So the language starts with types and their values, and the next chapter writes a first proof with them.

This chapter introduces the basic types one at a time: natural numbers, Unit and Void, pairs, alternatives, functions, types themselves, equality, and forall and exists. Each section shows how to write the type, how to build its values, and what the checker says about a value of the wrong type.

Every example in this reference is checked. When the checker rejects an example, its error message appears as a // Error: comment on the line at fault. Click a name in an example to see the checked kernel term behind it, with its type and context. Open in workspace opens the example in the proof workspace, where you can edit and check it. To check files on your own computer, use the command-line checker.

Every value has a type

A Cubist file is a list of declarations. The simplest names a value:

def seven := 7;

def seven := 7; names the value 7. The checker works out its type, Nat, the type of natural numbers. Read x : T as “x has type T”: here seven : Nat.

Stating the type: exact

A declaration can also state its type, after a colon. The value then goes in a block between braces, and the statement exact value; gives it:

def seven_again : Nat {
  exact 7;
}

A short value can also follow the type directly: def seven_again : Nat := 7; means the same. Throughout Cubist, := gives a name its value, and = always means equality. The checker accepts the declaration only when the value really has the stated type. exact is the simplest statement a block can hold. The following chapters use blocks to build proofs one step at a time, and the chapter on proof blocks lists every statement.

Natural numbers

Nat is the type of natural numbers 0, 1, 2, …. They are built from 0 and succ, the successor: succ(n) is n + 1.

By default, a numeral is a Nat in this unary form: 3 is shorthand for succ(succ(succ(0))). It is not a machine integer, so a numeral’s size is the size of its term; numerals go up to 256. Binary literals such as 0b110 belong to a separate type, BinaryNat, described with the inductive types.

Addition + and multiplication * are defined in the arithmetic library, which a file loads with import naturals; at its start. evaluate term expecting value; checks what a term computes to:

import naturals;

def three := succ(succ(succ(0)));

evaluate three expecting 3;
evaluate 2 + 3 expecting 5;
evaluate 2 * 3 expecting 6;

Without the import, + has no definition. A wrong expectation is reported with the actual value:

def five := 2 + 3;  // Error: Untranslated name: add
import naturals;

evaluate 2 + 2 expecting 5;  // Error: The term evaluates to 4, not 5.

Unit

Unit is the type with exactly one value, tt. A value of Unit carries no information: there is only one thing it could be. Read as a statement, Unit is trivially true.

def nothing_much : Unit {
  exact tt;
}

def forget(n : Nat) : Unit {
  exact tt;
}

If you know C, its void corresponds to Unit, not to Void: a C function returning void does return, just without information, like a Cubist function returning tt. A value of another type is not a Unit:

def not_unit : Unit {
  exact 0;  // Error: Type mismatch: found Nat, expected Unit.
}

Void

Void is the empty type. Like the empty set, it has no values, so no closed term of type Void can be written. Read as a statement, Void is falsehood. Since there is nothing to give, every attempt to produce a Void fails:

def something : Void {
  exact tt;  // Error: Type mismatch: found Unit, expected Void.
}

A value of Void can still be assumed, as a parameter. absurd(v) turns such a value into a value of any type: no case can arise, because no v exists. The chapter on terms uses this for negation, written A -> Void.

def from_nothing(v : Void) : Nat {
  exact absurd(v);
}

Pairs: and

A and B is the type of pairs (a, b) with a : A and b : B. Three or more components are written in one tuple, (1, 2, 3), with the type Nat and Nat and Nat.

def pair : Nat and Unit {
  exact (3, tt);
}

def triple : Nat and Nat and Nat {
  exact (1, 2, 3);
}

A pair needs its type stated: the checker does not guess it.

def loose := (3, tt);  // Error: Pair requires an expected type.

Alternatives: or

A or B is the type of values that are either a value of A, written left(a), or a value of B, written right(b). A value remembers which side it came from. Such a type is also called a sum. The chapter on terms shows how to take such a value apart.

def a_number : Nat or Unit {
  exact left(3);
}

def no_number : Nat or Unit {
  exact right(tt);
}

More than two alternatives

or groups to the right: Unit or Unit or Nat means Unit or (Unit or Nat). So left picks the first type, and right steps into the rest, where left and right pick again:

def first_of_three : Unit or Unit or Nat {
  exact left(tt);
}

def second_of_three : Unit or Unit or Nat {
  exact right(left(tt));
}

def third_of_three : Unit or Unit or Nat {
  exact right(right(5));
}

Each right steps in once, so a value deeper in the list needs every step on the way:

def skipped_step : Unit or Unit or Nat {
  exact right(5);  // Error: Type mismatch: found Nat, expected Unit or Nat.
}

right(5) offers 5 as a value of the rest, Unit or Nat, which is itself an or. right(right(5)) is the value meant.

Parentheses make a different type. In (Unit or Unit) or Nat, left first picks between the two units:

def second_unit : (Unit or Unit) or Nat {
  exact left(right(tt));
}

def the_number : (Unit or Unit) or Nat {
  exact right(5);
}

Functions: ->

A -> B is the type of functions from A to B. fun (n : Nat) => n + n is the function that doubles a number, of type Nat -> Nat. A declaration with parameters defines a function in one step, and f(x) applies it:

import naturals;

def double(n : Nat) := n + n;

def double_again := fun (n : Nat) => n + n;

evaluate double(4) expecting 8;
evaluate double_again(4) expecting 8;
import naturals;

def double(n : Nat) := n + n;

def wrong_argument := double(tt);  // Error: Type mismatch: found Unit, expected Nat.

The argument tt has type Unit, but double takes a Nat.

Several parameters

A function can take several parameters, separated by commas, and f(a, b) applies it to all of them. Consecutive parameters of the same type can share it: (m, n : Nat) means (m : Nat, n : Nat). The same works in fun:

import naturals;

def sum(m : Nat, n : Nat) := m + n;

def sum_again(m, n : Nat) := m + n;

def sum_fun := fun (m, n : Nat) => m + n;

evaluate sum(3, 4) expecting 7;
evaluate sum_again(3, 4) expecting 7;
evaluate sum_fun(3, 4) expecting 7;

The comma between names is required:

def sum_spaced(m n : Nat) := m + n;  // Error: Separate names with commas: (n, m : Nat)

A function of two numbers has type Nat -> Nat -> Nat: given m, it returns a function that waits for n. So arguments can be supplied a few at a time, and sum(3) is the function that adds 3:

import naturals;

def sum(m, n : Nat) := m + n;

def add_three := sum(3);

evaluate add_three(4) expecting 7;

Functions in a block: intro

A function can also be built in a block, like any other value. When the type to give is a function type A -> B, intro a; takes the input: it names it a, of type A, and what remains to give is a value of B, which can use a. With several names, separated by commas, intro takes several inputs at once:

import naturals;

def double : Nat -> Nat {
  intro n;        // n : Nat; what remains to give is a Nat
  exact n + n;
}

def sum : Nat -> Nat -> Nat {
  intro m, n;     // m : Nat and n : Nat; what remains to give is a Nat
  exact m + n;
}

evaluate double(4) expecting 8;
evaluate sum(3, 4) expecting 7;

This double is the same function as def double(n : Nat) := n + n;. The next chapter calls the type that remains to give the goal, and the names available the context. In the proof workspace, clicking a line number of a block shows both. A type that is not a function has no input to take:

def seven : Nat {
  intro n;  // Error: intro requires a dependent function goal.
  exact 7;
}

Nat is not a function type. The message’s dependent function types are the forall types below, and A -> B is one of them.

Types are values too

A type is itself a value, of a type called a universe. Nat, Unit and Nat and Unit have type U0, the universe of small types. U0 itself has type U1, the next universe. So types can be named, and functions can build them:

def Pair := Nat and Unit;

def p : Pair {
  exact (1, tt);
}

def Twice(A : U0) := A and A;

def q : Twice(Nat) {
  exact (1, 2);
}

def nat_is_a_type : U0 {
  exact Nat;
}

A universe does not contain itself:

def too_big : U0 {
  exact U0;  // Error: Type mismatch: found U1, expected U0.
}

Equality: =

For two values x and y of the same type, x = y is a type: the statement that they are equal. Its values are evidence of that equality. refl(x), short for reflexivity (every value is equal to itself), is evidence that x = x, and the checker also accepts it as evidence of x = y whenever x and y compute to the same value:

import naturals;

def two_plus_two : 2 + 2 = 4 {
  exact refl(4);
}

def seven_is_seven : 7 = 7 {
  exact refl(7);
}

2 + 2 computes to 4, so refl(4) proves 2 + 2 = 4. Values that are not equal have no such evidence:

import naturals;

def wrong_sum : 2 + 2 = 5 {
  exact refl(4);  // Error: Type mismatch: found 4 = 4, expected 2 + 2 = 5.
}

The message shows both types as they would be written in a file. An equality is a type like any other, so it can be a parameter, an assumption to reason from, or part of a larger type. Equalities that do not hold by computation, such as n + 0 = n for a variable n, need a proof; the chapter on equality and paths describes the tools.

Dependent types: forall and exists

A function’s result type can depend on its argument. forall x : A. B is the type of functions that take any x : A and return a value of B, where B may mention x. A -> B is the special case where it does not. The dot ends the type of x, and the body follows it. Several names can share the type, as parameters do: forall x, y : A. B.

// `and` binds tighter than `->`, so `A -> A and A` means `A -> (A and A)`.
def duplicate : forall A : U0. A -> A and A {
  exact fun (A : U0, a : A) => (a, a);
}

// The same function, built with intro.
def duplicate_again : forall A : U0. A -> A and A {
  intro A, a;     // A : U0 and a : A; what remains to give is A and A
  exact (a, a);
}

def one_one := duplicate(Nat, 1);

duplicate takes a type A and then a value of that type; intro A, a; takes the two inputs of duplicate_again in the same order. Its result type, A and A, depends on which type it was given: duplicate(Nat, 1) is the pair (1, 1). The chapter on terms lists the full precedence of the operators. The result must fit the type the argument chose:

def duplicate : forall A : U0. A -> A and A {
  exact fun (A : U0, a : A) => (a, 0);  // Error: Type mismatch: found Nat, expected A.
}

A comma cannot end the type. In a parameter list such as (P : Nat -> U0, f : forall n : Nat. P(n)), a comma separates parameters, so it would read as the start of the next one:

// Error: End forall's type with a dot: forall n : Nat. P(n)
def identity_on_nat : forall n : Nat, Nat := fun (n : Nat) => n;

A forall type is itself a value, like every type. Compare a function that builds a type with a single type that quantifies over all types:

def Twice(A : U0) := A and A;

def AlsoTwice : U1 {
  exact forall A : U0. A and A;
}

Twice is a function from types to types: Twice(Nat) is Nat and Nat. AlsoTwice is one type: the type of functions that give a pair of values in every type. It quantifies over all of U0, so it lives in the next universe, U1. It has no values, because Void has no pair of values.

exists x : A. B is the type of pairs whose second component’s type depends on the first: a value x : A, together with a value of B for that x.

def pointed : exists A : U0. A {
  exact (Nat, 3);
}

def two_of_a_kind : exists A : U0. A and A {
  exact (Nat, (1, 2));
}

The first component decides the type of the second:

def pointed : exists A : U0. A {
  exact (Nat, tt);  // Error: Type mismatch: found Unit, expected Nat.
}

Read as statements, forall and exists are the quantifiers “for all” and “there exists”. A value of exists n : Nat. P(n) is a witness n together with evidence that P(n) holds. The next chapter proves a first statement with both: forall n : Nat. exists m : Nat. lt(n, m), every number has a greater one.
