Types at a glance

Propositions are types, and a proof of a proposition is an element of it. There is no separate sort of propositions. A -> B is implication, A and B is conjunction, A or B is a disjunction that records which side holds, and A -> Void is negation.

exists is a pair with an actual witness. It is not truncated. Likewise, or keeps the side a value is on. For mere existence, use propositional truncation.

Functions

fun (x : A) => body is the function sending x to body. Its type is A -> B when body : B does not mention x, and forall x : A. B(x) when it does. Binders can be grouped like parameters:

SourceMeans
fun (x, y : A) => bodyfun (x : A) => fun (y : A) => body
fun (a : A, b : B) => bodyBinders with different types, separated by commas, exactly as in a parameter list
fun x => bodyOne binder whose type is taken from the expected function type
 
def constant(A, B : U0) := fun (a : A, b : B) => a;

def second(A : U0) := fun (x, y : A) => y;

def twice(A : U0, f : A -> A) := fun (x : A) => f(f(x));

A binder without a type needs an expected function type, from a stated result type, an exact goal or typed. In compose, each untyped binder reads its type from the goal: g : B -> C, then f : A -> B, then x : A.

import nat;

def compose(A, B, C : U0) : (B -> C) -> (A -> B) -> A -> C {
  exact fun g => fun f => fun x => g(f(x));
}

def successor_function := typed(Nat -> Nat, fun n => succ(n));
def no_expected_type := fun x => x;  // Error: Untyped lambda requires an expected function type.

All typed binders go in one parenthesized list, separated by commas, as in parameters. An untyped binder stands alone: fun x => fun y => ….

Currying

A function of several parameters takes them one at a time. Its type is a chain of arrows, A -> B -> C, which reads A -> (B -> C): given an A, it returns a function that waits for a B. This is called currying. So f(a, b) means f(a)(b), and f(a) alone is a function waiting for the rest. Arguments can be supplied all at once, one at a time, or a few at a time; every argument is written, or is a hole that the others determine.

import nat;
use nat;

def apply_twice(A : U0, f : A -> A, a : A) := f(f(a));

// All at once, one at a time, or a few at a time.
def five := apply_twice(Nat, fun (n : Nat) => succ(n), 3);
def five_again := apply_twice(Nat)(fun (n : Nat) => succ(n))(3);
def add_two := apply_twice(Nat, fun (n : Nat) => succ(n));
def twice_on_nat := apply_twice(Nat);

evaluate add_two(3) expecting five;
evaluate twice_on_nat(fun (n : Nat) => n + n, 3) expecting 12;

Each argument turns the function into one that waits for the remaining ones:

> typeof apply_twice;
forall A : U0. (A -> A) -> A -> A
> typeof apply_twice(Nat);
(Nat -> Nat) -> Nat -> Nat
> typeof add_two;
Nat -> Nat
> evaluate add_two;
fun (a : Nat) => succ(succ(a))

apply_twice(Nat) is a function of the other two parameters, and add_two, with a function supplied too, waits only for the number. Evaluating it shows the function it is: it applies succ twice.

Only a function can be applied:

import nat;
use nat;

def not_a_function := 0(1);  // Error: Source application is not a function.

Dependent functions

In forall x : A. B(x), the result type depends on the argument. Applying f : forall n : Nat. P(n) to 0 gives an element of P(0). forall x, y : A. B abbreviates two nested quantifiers over the same type.

import nat;
use nat;

def apply_at_zero(P : Nat -> U0, f : forall n : Nat. P(n)) : P(0) {
  exact f(0);
}

def swap_arguments(A : U0, P : A -> A -> U0, f : forall x, y : A. P(x, y)) : forall y, x : A. P(x, y) {
  intro y, x;
  exact f(x, y);
}

The argument decides the result type, so f(0) does not prove P(1):

import nat;
use nat;

def wrong_index(P : Nat -> U0, f : forall n : Nat. P(n)) : P(1) {
  exact f(0);  // Error: Type mismatch: found P(0), expected P(1).
}

Functions defined by cases, on sums below or on inductive types, use match. A function that calls itself on smaller values uses structural recursion.

Holes and named arguments

An argument that the call's other arguments determine can be left as a hole, _. The elaborator reads it off the types of the other arguments and the type the call is expected to have, and the kernel checks the call as though the argument had been written. In joined, the carrier and the three endpoints come from the two paths:

import nat;

def concat(U < UU0, A : U, x, y, z : A, p : x = y, q : y = z) : x = z := trans(p, q);

def joined(a, b, c : Nat, p : a = b, q : b = c) : a = c := concat(U0, _, _, _, _, p, q);

A named argument, x := e, gives the parameter x of a definition. Each parameter before the last one given that no argument gives is a hole, and the arguments without names fill the other parameters in order. The parameters after the last one given are left for a later application, as in f(a):

import nat;

def apply(U < UU0, A, B : U, f : A -> B, a : A) : B := f(a);

def by_name(n : Nat) : Nat := apply(U0, a := n, f := fun x => succ(x));
def successor : Nat -> Nat := apply(U0, f := fun (x : Nat) => succ(x));

In by_name, A and B are holes: n gives A and the expected type gives B. The untyped fun x => succ(x) waits for both, then is checked against Nat -> Nat. Click a hole in the workspace to see what it became.

A hole is filled only by what determines it. Nothing is searched for, so a hole whose type has an inhabitant, such as a proof of n = n, is still refused. The arguments of a built-in form, such as refl, and of a constructor are written out:

import nat;

def same(U < UU0, A : U, a : A) : A := a;

def no_search(n : Nat) : n = n := same(U0, n = n, _);  // Error: Nothing determines the parameter a of same, of type n = n: not the other arguments' types, nor the type expected of the call. Give it explicitly.

Cumulativity can leave a type open: Nat is in U0, and in every larger universe too. Where a larger universe would do as well, the hole is refused rather than guessed:

import nat;

def same(U < UU0, A : U, a : A) : A := a;

def universe_open := same(U2, _, Nat);  // Error: The parameter A of same is not determined: U0 fits, and so would a larger universe. Give it explicitly.

Bounds on both sides settle it: in pinned, T : U1 needs A to hold T, and the expected type needs A to be at most U1, so A is U1.

def same(U < UU0, A : U, a : A) : A := a;

def pinned(T : U1) : U1 := same(U2, _, T);

Universe arguments

A universe argument can be a hole too. It is the least universe the call needs: the largest of the universes the other arguments' types say it must contain, or the one an equality of types fixes. In same(_, Nat, n), A := Nat is in U0, so U is U0. Where nothing bounds it and the call's type does not mention it, any universe would do, and it is U0; where the call's type does mention it, it is refused:

import nat;

def same(U < UU0, A : U, a : A) : A := a;

def at_nat(n : Nat) : Nat := same(_, Nat, n);
def at_types(T : U1) : U1 := same(_, U1, T);
import nat;

def the_universe(U < UU0, n : Nat) : next(U) := U;

def which(n : Nat) := the_universe(_, n);  // Error: Nothing determines the universe U of the_universe: no argument's type bounds it, and the call's type depends on it. Give it explicitly.

Implicit parameters

Parameters in double braces, {{ … }}, before a definition's parameter list are implicit: a call reads them off its other arguments and the type expected of it, universes included, and gives only the others, in parentheses. Each implicit parameter before the last argument given is a hole. So append reads its universe and element type off its lists:

import lists;
use nat;

def three := length(append(cons(1, typed(List(U0, Nat), nil)), cons(2, cons(3, nil))));
evaluate three expecting 3;

def concat{{U < UU0, A : U, x, y, z : A}}(p : x = y, q : y = z) : x = z := trans(p, q);

def joined(a, b, c : Nat, p : a = b, q : b = c) : a = c := concat(p, q);

To give implicit arguments yourself, write them in double braces after the name, in order: concat{{U0, Nat}}(p, q) gives U and A, and the endpoints after them are still inferred. _ leaves one to infer. Inside them, a named argument gives an implicit parameter by its name, as concat{{A := Nat}}(p, q), and the others fill the rest in order; an implicit parameter is not named in parentheses, nor an explicit one in double braces:

import nat;

def concat{{U < UU0, A : U, x, y, z : A}}(p : x = y, q : y = z) : x = z := trans(p, q);

def all_given(a, b, c : Nat, p : a = b, q : b = c) : a = c := concat{{U0, Nat, a, b, c}}(p, q);
def middle(a, b, c : Nat, p : a = b, q : b = c) : a = c := concat{{_, _, _, b}}(p, q);
def named(a, b, c : Nat, p : a = b, q : b = c) : a = c := concat{{A := Nat}}(p, q);

Double braces settle what the call leaves open. Here T : U0 and the expected type U1 both fit A := U0 and A := U1:

def same{{U < UU0, A : U}}(a : A) : A := a;

def open_type(T : U0) : U1 := same(T);  // Error: The parameter A of same is not determined: U0 fits, and so would a larger universe. Give it explicitly.
def settled(T : U0) : U1 := same{{_, U0}}(T);

An argument whose type applies a definition, as Tagged(U0, Unit), and a parameter's type that applies the same definition, as Tagged(U, A), are compared unfolded first. Where that leaves a parameter open, the other arguments and the expected type settle it if they can; only then are the two matched argument by argument. So the arguments are read off even where the definition's value forgets them: Tagged(U, A) is Nat whatever A is, and untag(t) still finds A := Unit. But an argument that does determine the parameter comes first: Family(n) is Nat too, and pick(a, refl(1)) finds n := 1 from refl(1), not 0 from a's type. When the arguments do not all match, nothing they solved is kept. A theory's homomorphisms rely on this: f.map reads f's models off f : Monoid.Hom(A, B) (homomorphisms).

import nat;
use nat;

def Tagged(U < UU0, A : U) : U0 := Nat;

def untag{{U < UU0, A : U}}(t : Tagged(U, A)) : Nat := t;

def tag_of(t : Tagged(U0, Unit)) : Nat := untag(t);

def Family(n : Nat) : U0 := Nat;

def pick{{n : Nat}}(a : Family(n), h : n = 1) : Nat := n;

def picked(a : Family(0)) : Nat := pick(a, refl(1));

The library's lists declares append{{U < UU0, A : U}}(xs, ys : List(U, A)). A definition that calls itself passes its implicit parameters unchanged: length(tail) in its own clause, never length{{U, A}}(tail). Double braces without parentheses give the function of the other parameters, so same{{U0, Nat}} is the identity on Nat; the name of a definition alone is the function of all its parameters. Goals and messages show a definition's implicit arguments in double braces too: append{{U, A}}(xs, nil) = xs.

A definition names its parameters apart, implicit or not, since a call can give each one by its name. So does a declared type, and each constructor its arguments:

def twice{{x : Nat}}(x : Nat) : Nat := x;  // Error: twice has two parameters named x: give each its own name.

Pairs and dependent pairs

(a, b) builds an element of A and B, or of exists x : A. B(x) when b : B(a). For an existential, the first component is the witness and the second is the evidence about it.

import nat;
use nat;

def two_units := typed(Unit and Unit, (tt, tt));

def two_exists : exists n : Nat. n = 2 {
  exact (2, refl(2));
}

A pair needs an expected type. (1, 2) could belong to Nat and Nat or to many exists types, and the elaborator does not guess. The expected type comes from a stated result type, a let's stated type, a function argument’s type or typed.

def unannotated := (1, 2);  // Error: Pair requires an expected type.

Tuples

The kernel has only binary pairs. Tuple notation (a, b, c) means (a, (b, c)), and the same notation works for types: A and B and C means A and (B and C). Explicit left nesting ((a, b), c) is a different shape.

import nat;
use nat;

def flat_triple : Nat and Unit and Nat {
  exact (1, tt, 2);
}

def nested_triple : (Nat and Unit) and Nat {
  exact ((1, tt), 2);
}

def first_of_three(t : Nat and Nat and Nat) : Nat {
  obtain (a, b, c) := t;
  exact a;
}

def one := first_of_three((1, 2, 3));

To pass a tuple as one argument, keep its parentheses: f((1, 2, 3)). f(1, 2, 3) passes three arguments. A tuple must match the nesting of its type:

import nat;
use nat;

def wrong_nesting : (Nat and Unit) and Nat {
  exact (1, tt, 2);  // Error: Expected a Sigma type for pair.
}

The formatter, npm run format:cubist, writes right-nested pairs as flat tuples and checks that the expanded syntax is unchanged. npm run linearize:cubist -- --check lists such pairs without changing any file.

Using a pair

p.1 and p.2 are the components of a pair p. For p : exists x : A. B(x), p.1 : A is the witness and p.2 : B(p.1) is the evidence about it. The dot is tight, with no space on either side. Projections apply to any term of a pair type, such as f(x).2, and they chain: the components of t : A and B and C are t.1, t.2.1 and t.2.2.

import nat;

def witness(P : Nat -> U0, e : exists n : Nat. P(n)) : Nat := e.1;

def evidence(P : Nat -> U0, e : exists n : Nat. P(n)) : P(e.1) := e.2;

def swap_pair(A, B : U0, p : A and B) : B and A := (p.2, p.1);

def last_of_three(t : Nat and Unit and Nat) : Nat := t.2.2;

Projections compute. A projection of a pair is its component, and every pair is the pair of its projections, so p = (p.1, p.2) holds by refl:

import nat;
use nat;

def pair_of_projections(A, B : U0, p : A and B) : p = (p.1, p.2) := refl(p);

evaluate typed(Nat and Nat, (2, 5)).2 expecting 5;

Only a pair has projections, and it has two. A projection of anything else is reported at the projection:

import nat;

def not_a_pair(n : Nat) : Nat := n.1;  // Error: Projection .1 requires a dependent pair; found a value of type Nat.
def third(t : Nat and Nat and Nat) : Nat := t.3;  // Error: A pair has only the projections .1 and .2.

In a proof block, obtain names the components instead. In a term, unpack pair as (a, b) return T { body; } does the same, where the result type T does not mention a or b:

import nat;

def first_number(pair : Nat and Nat) :=
  unpack pair as (a, b) return Nat { a; };

def swap(pair : Nat and Unit) :=
  unpack pair as (n, u) return Unit and Nat { typed(Unit and Nat, (u, n)); };
import nat;

// Error: unpack requires a dependent pair.
def not_a_pair(n : Nat) := unpack n as (a, b) return Nat { a; };

When the result type depends on the pair itself, use pair_induction(motive, branch, pair). For pair : exists x : A. B(x), the branch takes x : A and y : B(x) and proves motive((x, y)). The result proves motive(pair).

def pair_is_itself(A : U0, B : A -> U0, p : exists x : A. B(x)) : p = p {
  exact pair_induction(fun (q : exists x : A. B(x)) => q = q,
    fun (x : A, y : B(x)) => refl(typed(exists x : A. B(x), (x, y))), p);
}

Sums

left(a) and right(b) build elements of A or B. Like pairs, they need an expected type, because the other side is not determined:

import nat;
use nat;

def unit_on_the_left := typed(Unit or Nat, left(tt));

def three_on_the_right : Unit or Nat {
  exact right(3);
}
def unannotated := left(tt);  // Error: Sum injection requires an expected type.

Case analysis: match

match works on sums and on declared inductive types, such as Nat and your own types. This section shows the sum cases.

match value return T { left x => …; right y => …; } computes a result of type T from each side. Each branch is an expression and ends with ;.

import nat;
use nat;

def to_number(value : Unit or Nat) := match value return Nat {
  left u => 0;
  right n => n;
};

def swap_sides(A, B : U0, value : A or B) := match value return B or A {
  left a => right(a);
  right b => left(b);
};

When the result type depends on the value, name it with as: match value as z return C(z) { … }. The left branch must produce C(left(x)) and the right branch C(right(y)).

import nat;
use nat;

def Shape(value : Unit or Unit) := match value return U0 {
  left a => Nat;
  right b => Unit;
};

def default(value : Unit or Unit) := match value as z return Shape(z) {
  left a => 0;
  right b => tt;
};

Shape needs no as: its result type, U0, is the same for both sides. An as name that the result type does not mention is accepted, with a warning:

import nat;
use nat;

def to_number(value : Unit or Nat) := match value as z return Nat {  // Warning: z is unused: the return type does not mention it.
  left u => 0;
  right n => n;
};
import nat;

def not_a_sum(n : Nat) := match n return Nat {  // Error: Nat has no constructor left: its constructors are zero, succ.
  left a => 0;
  right b => 1;
};

The result type is the expected type of each branch, so right(a) needs no annotation. In a proof block, the match statement takes a sum apart with a block for each side, each proving the goal at its side.

Unit, Void and negation

tt is the element of Unit. Void has no elements: absurd(impossible) turns impossible : Void into an element of any expected type. Negation is A -> Void; there is no not keyword.

Unit and Void are reserved, as the keywords that begin a term or a statement are (fun, match, let, exact and the others): no declaration, parameter, binder, pattern or field can take their names, since checking relies on what they mean. A word that means something only in one place stays an ordinary name elsewhere: def, theory and evaluate at the start of a declaration or a directive, sort and law in a theory, prop in a header.

def Unit : U0 := Nat;  // Error: Unit is reserved, as a keyword or a built-in type of the language; pick another name.
def anything_from_void(A : U0, impossible : Void) : A {
  exact absurd(impossible);
}

def double_negation_intro(A : U0, a : A) : (A -> Void) -> Void {
  intro not_a;
  exact not_a(a);
}

def unit_is_tt(u : Unit) : u = tt {
  exact unit_induction(fun (v : Unit) => v = tt, refl(tt), u);
}

unit_induction(motive, base, value) proves motive(value) from base : motive(tt). absurd needs to know the type to produce:

// Error: absurd requires an expected type.
def unannotated(impossible : Void) := absurd(impossible);

Numbers and arithmetic

Nat is built from 0 and succ. A numeral is notation for repeated succ: 3 is succ(succ(succ(0))), not a machine integer. Numerals go up to 256.

import nat;
use nat;

def three := succ(succ(succ(0)));

def three_is_three : three = 3 {
  exact refl(3);
}
def too_big := 257;  // Error: Numerals are limited to 256 in this version.

The operators +, *, < and <= are notation for add, mul, isLt and le, which the arithmetic library defines. Import it with import nat;. The operators are not overloaded by the types of their operands: they mean the add and mul in scope, Nat's here, unless open binds them to a model's operations for a block.

import nat;
use nat;

def two_times_three : 2 * 3 = 6 {
  exact refl(6);
}

def two_below_three : 2 < 3 {
  exact tt;
}

Closed arithmetic computes, so refl(6) proves 2 * 3 = 6. The order is defined by computation too: 2 < 3 computes to Unit, proved by tt, and 3 < 2 computes to Void. Without the import, neither the numerals nor the notation have a definition:

def four := 2 + 2;  // Error: Untranslated name: Nat

Addition recurses on its first argument. 0 + n computes to n, but n + 0 is stuck on the variable n, so it needs a proof by induction. The library proves it as nat_add_zero(n).

import nat;
use nat;

def zero_plus(n : Nat) : 0 + n = n {
  exact refl(n);
}

def plus_zero(n : Nat) : n + 0 = n {
  exact nat_add_zero(n);
}
import nat;
use nat;

def plus_zero_by_computation(n : Nat) : n + 0 = n {
  exact refl(n);  // Error: Type mismatch: found n = n, expected n + 0 = n.
}

nat proves the laws of its arithmetic, each by induction or from the others:

LawsStatements
Additionnat_zero_add, nat_add_zero, nat_add_succ, nat_add_assoc, nat_add_comm, and the regroupings nat_add_left_comm, a + (b + c) = b + (a + c), and nat_add_interchange, (a + b) + (c + d) = (a + c) + (b + d)
Multiplicationnat_mul_zero, nat_mul_succ, nat_one_mul, nat_mul_one, nat_mul_comm, nat_mul_assoc, and distributivity, nat_add_mul, (x + y) * z = x * z + y * z, and nat_mul_add, x * (y + z) = x * y + x * z

import nat;
use nat;

def distributes(a, b : Nat) : 2 * (a + b) = 2 * a + 2 * b {
  exact nat_mul_add(2, a, b);
}

// 2 when a exceeds b, 1 when they are equal, 0 when b exceeds a.
def compare(a, b : Nat) : Nat := match nat_trichotomy(a, b) return Nat {
  left above => 2;
  right rest => match rest return Nat {
    left same => 1;
    right below => 0;
  };
};

evaluate compare(4, 3) expecting 2;
evaluate compare(3, 3) expecting 1;

The library builds the integers and the rationals from the naturals, as quotients, and the algebraic structures they carry. Induction on Nat and binary numerals are described in natural numbers and inductive types.

Expected types and typed

Several forms need an expected type: pairs, left and right, absurd, and untyped fun x =>. The expected type comes from:

  • the stated result type of a block declaration, through exact;
  • the type in let name : T;
  • the parameter type, when the term is an argument of a function;
  • the result type of a match branch;
  • typed(T, term), which checks term against T.
import nat;
use nat;

def number := typed(Nat, 3);

def successor := typed(Nat -> Nat, fun n => succ(n));

def unit_on_the_right := typed(Nat or Unit, right(tt));
import nat;

def not_a_number := typed(Nat, tt);  // Error: Type mismatch: found Unit, expected Nat.

Precedence

From tightest to loosest:

  1. application f(a) and projection p.1, from left to right, so f(a).2(b) applies the second component of f(a) to b;
  2. interval application p @ i, for cubical paths;
  3. *;
  4. +;
  5. =, <, <=;
  6. and;
  7. or;
  8. ->.

->, and and or group to the right. The other operators group to the left. The body of fun, forall and exists extends as far as possible. So A -> B -> C means A -> (B -> C), and forall x : A. P(x) -> Q(x) means forall x : A. (P(x) -> Q(x)).

def arrows_group_right(A, B, C : U0, f : A -> B -> C) : A -> (B -> C) {
  exact f;
}

def and_before_or(A, B, C : U0, x : A and B or C) : (A and B) or C {
  exact x;
}

Comparisons do not chain. 1 < 2 < 3 means (1 < 2) < 3, which compares a type with a number. Write (1 < 2) and (2 < 3).

import nat;
use nat;

def chained : 1 < 2 < 3 {
  exact tt;  // Error: Type mismatch: found U0, expected Nat.
}
