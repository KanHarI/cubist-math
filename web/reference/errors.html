How to read an error

Every rejected example in this reference shows its error as a // Error: comment, on the line where the checker reports it. This chapter lists those messages by topic, with what each means, what to do, and where an example shows it. Parts in italics stand for names or numbers from your source.

An error names the declaration it belongs to, and the workspace marks the statement it points at. A rejected declaration is not added, so every declaration that uses it fails too, with “Untranslated dependency”. Fix the first error in a file first.

Reading the source

These are reported before anything is checked, at the first token that does not fit.

MessageMeaning and fixExample
“Expected a declaration or directive: …”A top-level item must be a declaration (def, opaque def, computable def) or a directive (evaluate, simp_rule, simp_set). There is no axiom declaration: take a hypothesis as a parameter.declarations
“Imports must come before declarations.”Move every import to the start of the file.files
“Unexpected character c”Source is ASCII. Write ->, forall and exists instead of symbols.names
“Expected a name.”A name cannot start with a digit, and every parameter needs a type.names, parameters
“Write := to give a value: …”A binding (def, have, let, obtain, simp_set) gives its value with :=; = is the equality type. The message shows the form to use.declarations
“Expected ';', found token”A missing semicolon, reported at the next token.declarations
“Separate binder groups with commas: fun (a : A, b : B) => …”A fun takes one parenthesized binder list, like a parameter list.functions
“Expected '=>', found token”Untyped binders cannot share a group. Write fun x => fun y => …, or give the binders a type.functions
“Expected '}', found ';'.”The braces of with unfolding hold one expression, without a semicolon.unfolding hints
“Expected '=', found token”A calc step is an equality; other relations cannot be chained yet.not yet available
“Expected a proof statement; found word”The word is not a statement. apply, refine and sorry do not exist yet.statements, not yet available
“Expected an expression, found '{'.”A block is not a term. Prove the part first with have.blocks
“Use obtain to unpack a pair.”let names one term; obtain takes a pair apart.let
“A pair pattern needs at least two components.”Write obtain (a, b) := pair;, or name the whole value with let.obtain
“Numerals are limited to 256 in this version.”Build larger numbers with arithmetic, or use binary literals.numbers, limits
“Binary literals are limited to 256 significant bits.”A resource limit of the parser.limits
“simp only requires an explicit rule list.”Write simp only [rules];, or plain simp; for the default rules.simplification
“simp only cannot exclude rules.”without removes default rules; simp only has none. Leave the rule out of the list instead.rule selection
“simp_rule priority must be an integer from 0 to 1000.”Choose a priority in range.registration

Names and declarations

MessageMeaning and fixExample
“Untranslated name: name”The name is not in scope. It may be declared later, be the declaration itself (there is no recursion), need an import (+ needs import naturals;), be misspelled, or not be a construct of the language, such as Interval as a type or a _ hole outside calc.order, numbers
“Untranslated dependency: name”The named declaration failed, so its users are blocked. Fix the named declaration.checking
“Definition symbol is already registered.”A name is declared twice in one module. Rename one.order
“Simplification rule name is already registered in this module.”Register each rule once per module.registration

Types and terms

MessageMeaning and fixExample
“Type mismatch: found A, expected B.”A term of type A is used where a B is needed, and the two are not equal by computation. The message shows both types in Cubist syntax, with definitions under their source names and redexes reduced; when the whole declaration is compared, both are its full statement. Check argument order, universes and endpoints. From rfl, it means the two sides are only equal propositionally: use a lemma, rw or simp. In a cases branch, the goal is not refined; use match.exact, conversion, cases
“Source application is not a function.”Something that is not a function is applied, or a function gets too many arguments.application, parameters
“Untyped lambda requires an expected function type.”Give the binder a type, or put the function where a function type is expected.functions
“Pair requires an expected type.”, “Sum injection requires an expected type.”, “absurd requires an expected type.”The form needs its type from context. Supply it with a stated result type, have name : T or typed(T, term).expected types
“Expected a Sigma type for pair.”A pair is checked against a type that is not a pair type, or a tuple does not match the nesting of its type.tuples
“unpack requires a dependent pair.”Only pairs can be unpacked.using pairs
“match requires a sum type.”match analyses A or B. Use induction for Nat.match

Proof blocks

MessageMeaning and fixExample
“Proof block has no conclusion.”The block ends without closing its goal. Add a closing statement; after ext, the new goal still needs one.statements, changing the goal
“Statements after exact are unreachable.”Nothing may follow a closing statement. Prove intermediate claims with have before closing.statements
“Statements after cases are not yet translated.”cases must end its block. Move the rest into the branches.cases
“intro requires a dependent function goal.”The goal is not a function type, or all its inputs are already introduced.intro
“obtain requires a dependent pair matching its pattern.”The value is not a pair, or the pattern’s nesting differs from its type’s.obtain
“cases requires a sum type.”cases splits A or B.cases

Equality and paths

MessageMeaning and fixExample
“Path endpoints do not match.”In trans(p, q), p must end where q starts.operations
“cong requires a path.”The second argument must be a path.operations
“Transport endpoints do not match.”The stated endpoints must be the path’s, in order. Transport backwards along sym(p).transport
“transport requires a path.”The fourth argument must be a path.transport
“Path induction endpoints/carrier do not match.”The type and endpoints passed to path_induction must be the path’s.path induction
“Based induction needs concrete universes.”The first two arguments of based_induction are universes.path induction

Equational reasoning and simplification

MessageMeaning and fixExample
“rfl requires a homogeneous equality goal.”The goal is not an equality.rfl
“calc step left endpoint does not match the preceding endpoint.”Adjacent steps must share an endpoint. Write _ for the previous right side.calc
“calc final endpoint does not match the goal.”The chain must end at the goal’s right side.calc
“calc requires a homogeneous equality goal.”The goal is not an equality.calc
“Rewrite occurrence n was not found (m eligible matches).”Fewer matches exist than requested, or none: the rule must be instantiated at exactly the subterm that appears. Rewriting never looks under binders.rw
“rw left an unresolved equality goal; add a following proof statement.”The rewrite worked, but the new goal does not hold by computation. Add another statement.rw
“rw requires a homogeneous equality proof.”Instantiate the rule fully, as in nat_add_zero(n), or use simp only.rw
“Rewrite match occurs in an unsupported dependent position.”The only match is in a dependent argument. Use an explicit cong.rw
“rw requires a homogeneous equality goal.”The goal is a type, not an equality. simp rewrites types.rw
“A simplification rule parameter is not determined by the matched side; supply arguments.”Matching cannot fix every parameter. Pass the missing arguments.simplification
“simp only left an unresolved equality goal; add a following proof statement.”The simplified goal does not hold by computation. Add a statement; the message may name a rule whose premise was not proved.simplification
“Rule name has an unproved premise at parameter n; …”A conditional rule could not fire. Supply a local proof with simp with [h].conditional rules
“Simplification cycle detected in the selected rules.”A rule rewrites its output back into its input, as commutativity does. Instantiate it at specific arguments.traversal
“… budget exceeded.”Rewriting, matching, term size or time hit a fixed bound. Narrow the rules with simp only, or split the proof.traversal
“simp at requires a local hypothesis: name.”simp … at h simplifies a hypothesis in the context, not a library lemma.rule selection
“A simplified hypothesis copy must be followed by a proof statement.”simp … at h as h2 leaves the goal open. Use h2 in a following statement.rule selection
“Simplification premise witness must be local: name.”with [h] lists hypotheses from the context.conditional rules

Cubical paths

MessageMeaning and fixExample
“Interval coordinates can only be used in interval arguments.”A coordinate is not a term. Use it only in @, flip, meet, join and faces.the interval
“path i => ... needs an expected Path or PathP type.”Use the shorthand where a path type is expected, or write path(family, body).shorthand
“over requires an expected PathP goal.”over proves dependent paths only.dependent paths
“ext requires equality of functions.”The goal is not an equality of functions.ext
“Composition tube disagrees with its base.”A wall does not start on the base. Check each wall at the base coordinate.composition

Interval and face formulas beyond 4,096 clauses fail with a lattice budget error. Split such a proof into named steps.

Conversion, assumptions and computability

MessageMeaning and fixExample
“No checked definition to unfold: name”Hints name top-level checked definitions only.unfolding hints
“Logical assumptions require a concrete universe and an explicit native context.”A library assumption was used without its universe argument. Write Truncate(U0, A).universes
“Too many arguments to name.”A library assumption got more arguments than its type allows.universes
“This computable declaration depends on non-computing assumptions: …”The declaration uses an assumption, directly or through a definition. The message names the chain. Replace that step, or drop computable.computable
“The evaluated term depends on non-computing assumptions: …”evaluate accepts only terms that use no assumption.evaluate
“The term evaluates to a, not b.”The normal forms differ; the message shows both.evaluate

Not yet available

These are planned; see the work plan. Until then, they are rejected:

def uses_apply(A B : U0, f : A -> B, a : A) : B {
  apply f;  // Error: Expected a proof statement; found 'apply'.
  exact a;
}
def unfinished : Nat {
  sorry;  // Error: Expected a proof statement; found 'sorry'.
}
def hole : Nat {
  exact _;  // Error: Untranslated name: _
}
import naturals;

def mixed(a b : Nat, h : a = b) : a <= b {
  calc {
    a = b by h;
    _ <= b by tt;  // Error: Expected '=', found '<='.
  }
}
  • apply, refine and sorry;
  • implicit or named arguments, and _ holes outside calc;
  • chains of relations other than equality in calc;
  • rewriting a hypothesis together with everything that depends on it: simp at makes a new copy instead;
  • solving premises of conditional rules that are not equalities;
  • user-declared inductive types and match on them, which replace today’s built-in eliminators.
