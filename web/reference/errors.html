How to read an error

Every error and warning has a code, such as E606 or W703. The code comes before the message wherever the checker reports one: error E606 at line 2:3 (wrong): Type mismatch: … on the command line, and E606: Type mismatch: … in the REPL and the workspace, where it links here. E codes come from the parser and the elaborator, K codes are refusals by the kernel, and W codes are warnings. A code keeps its meaning as the message’s wording changes, and this page has an entry for each, at errors.html#E606: the sections below explain the codes this reference shows, and every code lists them all.

Every rejected example in this reference shows its error as a // Error: comment, on the line where the checker reports it. An accepted example that draws a warning shows it as a // Warning: comment in the same way. This chapter lists those messages by topic, with what each means, what to do, and where an example shows it. Parts in italics stand for names or numbers from your source.

An error names the declaration it belongs to, and the workspace marks the statement it points at. A rejected declaration is not added, so every declaration that uses it fails too, with “Untranslated dependency”. Fix the first error in a file first.

Reading the source

These are reported before anything is checked, at the first token that does not fit.

CodeMessageMeaning and fixExample
E151“Imports must come before declarations.”Move every import to the start of the file.files
E106“Unexpected character c”Source is ASCII. Write ->, forall and exists instead of symbols.names
E110“Expected a name.”A name cannot start with a digit.names
E112“Expected ':' or '<', found token”Every parameter needs a type, after a colon, or, for a universe variable, a bound after <.parameters
E109 E153“Write := to give a value: …”A binding (def, let, obtain, simp_set) gives its value with :=; = is the equality type. The message shows the form to use.declarations
E108“Expected ';', found token”A missing semicolon, reported at the next token.declarations
E117“Separate names with commas: (n, m : Nat)”Names that share a type are separated by commas, in parameters, fun binders and after forall or exists.several parameters
E128“End forall's type with a dot: forall n : Nat. P(n)”A dot, followed by a space, separates a quantifier’s type from its body; the same holds for exists. A comma would read as the next parameter.forall and exists
E108“Expected '}', found ';'.”The braces of with unfolding hold one expression, without a semicolon.unfolding hints
E108“Expected '=', found token”A calc step is an equality; other relations cannot be chained yet.not yet available
E139“Expected a proof statement; found word”The word is not a statement. apply, refine and sorry do not exist yet.statements, not yet available
E136“have was removed: write let name : T := term; …”let has have's forms: let name : T := term; and let name : T { … }.local lemmas
E137“show was removed: …”Prove the restated goal, let h : T { … }, then close with exact h;.restating the goal
E138“suffices was removed: …”Prove the claim first, let h : T { … }, then prove the goal from h.reasoning backwards
E164“cases was removed: write match value { left(a) => { … } right(b) => { … } }.”The match statement takes a sum apart, each clause proving the goal at its side. Write match where the source had cases; the clauses may stay as they were.taking a sum apart
E123“Expected an expression, found '{'.”A block is not a term. Prove the part first with let name : T { … }.blocks
E140“Use obtain to unpack a pair.”let names one term; obtain takes a pair apart.let
E120“A pair has only the projections .1 and .2. …”A projection is .1 or .2. A tuple nests pairs to the right, so the third component of (a, b, c) is .2.2.using pairs
E131“A pair pattern needs at least two components.”Write obtain (a, b) := pair;, or name the whole value with let.obtain
E122“Numerals are limited to 256 in this version.”Build larger numbers with arithmetic, or use binary literals.numbers, limits
E121“Binary literals are limited to 256 significant bits.”A resource limit of the parser.limits
E144“simp only requires an explicit rule list.”Write simp only [rules];, or plain simp; for the default rules.simplification
E145“simp only cannot exclude rules.”without removes default rules; simp only has none. Leave the rule out of the list instead.rule selection
E149“simp_rule priority must be an integer from 0 to 1000.”Give a priority in range.registration

Names and declarations

CodeMessageMeaning and fixExample
E343“Untranslated name: name”The name is not in scope. It may be declared later, be the declaration itself (there is no recursion), need an import (+ needs import nat;), be misspelled, or not be a construct of the language, such as Interval as a type.order, numbers
E340“Untranslated dependency: name”The named declaration failed, so its users are blocked. Fix the named declaration.checking
E604“Definition symbol is already registered.”A name is declared twice in one module. Rename one.order
E327“Simplification rule name is already registered in this module.”Register each rule once per module.registration
E568“f has two parameters named x: give each its own name.”A definition's parameters, implicit or not, and a declared type's, have distinct names, since a call can give each one by its name. A constructor's arguments do too (E569). Rename one.implicit parameters

Types and terms

CodeMessageMeaning and fixExample
E606“Type mismatch: found A, expected B.”A term of type A is used where a B is needed, and the two are not equal by computation. The message shows both types in Cubist syntax, with definitions under their source names and redexes reduced; when the whole declaration is compared, both are its full statement. Check argument order, universes and endpoints. From rfl, it means the two sides are only equal propositionally: use a lemma, rw or simp.exact, conversion
E352“Source application is not a function.”Something that is not a function is applied.currying
E382“f takes n arguments; this is one more.”The call gives more arguments than the function takes. Remove the extra ones, or apply the result separately if it is itself a function.parameters
E388“Nothing determines the parameter x of f, of type T: …”A hole _, or a parameter left out before a named argument, is not fixed by the other arguments' types or by the type expected of the call. Holes are never filled by searching for a term of their type. Write the argument.holes
E392“The parameter x of f is not determined: U0 fits, and so would a larger universe. …”The hole is a type that cumulativity leaves open: a type in U0 is in every larger universe too. A bound from the expected type that agrees settles it; otherwise write the type: by position, in double braces for an implicit parameter, as same{{_, U0}}(T), or by name.holes
E391“Nothing determines the universe U of f: …”A universe hole that no argument's type bounds, where the call's type depends on it. Write the universe: by position, in double braces for an implicit one, as f{{U0}}(…) or f{{U := U0}}(…), or by name in parentheses for an explicit one.universe arguments
E385“A hole _ stands for an argument of a call, …”A hole is an argument of a call to a definition or a function, which the call determines. Anywhere else, such as a whole proof, write the term.holes
E346“Untyped lambda requires an expected function type.”Give the binder a type, or put the function where a function type is expected.functions
E350 E414 E415“Pair requires an expected type.”, “Sum injection requires an expected type.”, “absurd requires an expected type.”The form needs its type from context. Supply it with a stated result type, let name : T or typed(T, term).expected types
E351“Expected a Sigma type for pair.”A pair is checked against a type that is not a pair type, or a tuple does not match the nesting of its type.tuples
E349“Projection .1 requires a dependent pair; found a value of type T.”Only a pair has projections. The message shows the type of the projected value.using pairs
E356“unpack requires a dependent pair.”Only pairs can be unpacked.using pairs

Inductive types and recursion

CodeMessageMeaning and fixExample
E561“The match has no case for c(…) in value.”No clause fits that constructor of the value, here or nested inside another pattern. Add a clause for it, or a variable or _ that covers it.patterns
E559“This clause is never reached: the clauses before it take every case it would.”Clauses are tried in order, and earlier ones, a variable or _ among them, already take every case this one fits. Move it before them, or remove it.patterns
E567“The match on a sum needs a clause for right: right(a) => { … }.”A match on A or B has a clause for each side, left(a) and right(b). Add the missing one.taking a sum apart
E519“nil needs an expected type, to know which List(…) it builds: write typed(List(…), nil).”A constructor of a parameterized type takes only its declared arguments, so the type’s arguments come from context. Give a result type, or use typed.parameters
E528“Nat has no constructor left: its constructors are zero, succ.”A match clause names a constructor that the matched type does not have, such as a sum’s left on Nat. Use the listed constructors.match
E557“c takes n arguments here, then its induction hypothesis if you name them: …”An induction clause names the constructor’s arguments, then optionally one hypothesis per recursive argument; it gave another number of names.induction
E547“loop is being defined: it can call itself only on an argument of a constructor”A definition calls itself, but its whole body is not a match on one of its parameters. Make it one, and recurse on a child bound by a clause.order, structural recursion
E552“The recursive call of f is not on an argument of the matched constructor: only structural recursion, …”A recursive call passes something other than a child bound by the clause, such as the original input or a new constructor value. Recurse on a child.structural recursion

Equational reasoning and simplification

CodeMessageMeaning and fixExample
E446“rfl requires a homogeneous equality goal.”The goal is not an equality.rfl
E450“calc step left endpoint does not match the preceding endpoint.”Adjacent steps must share an endpoint; the message shows both. Write _ for the previous right side.calc
E451“calc final endpoint does not match the goal.”The chain must end at the goal’s right side; the message shows where it ends and what the goal needs.calc
E448“calc requires a homogeneous equality goal.”The goal is not an equality.calc
E442“Rewrite occurrence n was not found (m eligible matches).”Fewer matches exist than requested, or none: the rule must be instantiated at exactly the subterm that appears. Rewriting never looks under binders. The message shows the goal that was searched.rw
E452“rw left an unresolved equality goal; add a following proof statement.”The rewrite worked, but the new goal does not hold by computation. The message shows that goal and the rewrites that changed it. Add another statement.rw
E431“rw requires a homogeneous equality proof.”Instantiate the rule fully, as in nat_add_zero(n), or use simp only.rw
E441“Rewrite match occurs in an unsupported dependent position.”The only match is in a dependent argument. Use an explicit cong.rw
E360“rw requires a homogeneous equality goal.”The goal is a type, not an equality. simp rewrites types.rw
E436“A simplification rule parameter is not determined by the matched side; supply arguments.”Matching cannot fix every parameter. Pass the missing arguments.simplification
E456“simp only left an unresolved equality goal; add a following proof statement.”The simplified goal does not hold by computation. The message shows it, the sides that changed and the rules that fired, and may name a rule whose premise was not proved. Add a statement.simplification
E456“Rule name has an unproved premise at parameter n; …”A conditional rule could not fire. Supply a local proof with simp with [h].conditional rules
E367“Simplification cycle detected in the selected rules.”A rule rewrites its output back into its input, as commutativity does. The message names the rules that brought the goal back. Instantiate them at specific arguments.traversal
E369“… budget exceeded.”Rewriting, matching or term size hit a fixed bound; the message shows the goal where the search stopped. Narrow the rules with simp only, or split the proof.traversal
E454“simp at requires a local hypothesis: name.”simp … at h simplifies a hypothesis in the context, not a library lemma.rule selection
E453“A simplified hypothesis copy must be followed by a proof statement.”simp … at h as h2 leaves the goal open. Use h2 in a following statement.rule selection
E331“Simplification premise witness must be local: name.”with [h] lists hypotheses from the context.conditional rules

A search, or a declaration, that uses up its fuel fails with “search ran out of search fuel: n kind.”, naming what ran out: subterm visits, candidate rules tried, rewrites, premise searches, term nodes walked or kernel queries. A search’s message also shows the goal where it stopped. The defaults are well above what the checked proofs need, so such a failure usually means a rule set that keeps rewriting. The kernel’s own step limit per operation and a checker’s time limit fail differently: “Kernel checking/reduction budget exhausted.” and “Declaration time limit exceeded.”

Theories and models

CodeMessageMeaning and fixExample
E803“T has two fields named f: give each its own name.”A model's fields are read by name, so a theory's fields, its own and its parents', have distinct names. Rename one.theories
E828“T gets the carrier M from P and Q with different kinds or indices: rename one, as in Q(M := …).”Two parents give a carrier of one name, merged into one carrier of the child only when both are sets, or both propositions, of one type. Rename it in one parent to keep them apart.extension
E817“T's models have no homomorphisms: …”A homomorphism preserves each operation, pushing each argument that holds a carrier forward and pulling one with a carrier left of an arrow back. An argument with a carrier on both sides of an arrow, a carrier with no h-level, and a few other forms leave a theory without homomorphisms; the message names which.homomorphisms
E834“use selects a model of a theory, such as m : Group(U0); this is a value of type A.”use puts a model's fields and notation in scope; the value given is not a model of a theory.use

CodeMessageMeaning and fixExample
E341“Interval coordinates can only be used in interval arguments.”A coordinate is not a term. Use it only in @, flip, meet, join and faces.the interval
E338“path i => ... needs an expected Path or PathP type.”Use the shorthand where a path type is expected, or write path(family, body).shorthand
E463“over requires an expected PathP goal.”over proves dependent paths only.dependent paths
E461“ext requires equality of functions.”The goal is not an equality of functions.ext
E604“Composition tube disagrees with its base.”A wall does not start on the base. Check each wall at the base coordinate.composition
E470“glue needs the Glue type it builds an element of: write typed(Glue(…), glue(…)).”A glue term is checked at a Glue type: give it one with typed, or use it where one is expected.Glue types
E472“unglue takes an element of a Glue type.”The argument of unglue is not of a Glue type.Glue types

Warnings

A warning does not reject anything: the declaration is checked. It marks a binding that is never used and can be removed; see warnings.

CodeMessageMeaning and fixExample
W703“k is unused: the return type does not mention it and the successor clause does not use it. …”The result type is the same for every number, and the successor branch does not use the predecessor. Omit as k.induction
W704“z is unused: the return type does not mention it. …”The result type is the same for every value. Omit as z.match
W705“x is unused in the body: write A -> … instead of forall x : A. ….”The quantified variable is never mentioned. Write A -> B for forall x : A. B, and A and B for exists x : A. B; they are the same types.exists and and
W702“name is never used after this let: remove it.”Nothing later in the block uses the name. Remove the statement.let

Not yet available

These are planned; see the work plan. Until then, they are rejected:

def unfinished : Nat {
  sorry;  // Error: Expected a proof statement; found 'sorry'.
}
import nat;

def hole : Nat {
  exact _;  // Error: A hole _ stands for an argument of a call, which the call's other arguments or the type expected of it determine; anywhere else, write the term.
}
import nat;

def mixed(a, b : Nat, h : a = b) : a <= b {
  calc {
    a = b by h;
    _ <= b by tt;  // Error: Expected '=', found '<='.
  }
}
  • sorry;
  • _ holes anywhere but a call's arguments;
  • chains of relations other than equality in calc;
  • rewriting a hypothesis together with everything that depends on it: simp at makes a new copy instead;
  • solving premises of conditional rules that are not equalities;
  • inductive families with indices, and mutually defined inductive types; see parameters and constructors.

Every code

Each error and warning the checker can report has a code. E codes come from the parser and the elaborator, which turn source into kernel terms; K codes are refusals by the C kernel, which checks those terms; W codes are warnings. This index lists every code with its message, where … stands for the part that varies. A code explained in the sections above links to its explanation. Many K messages guard the kernel against malformed terms, and a term the elaborator builds does not reach them.
