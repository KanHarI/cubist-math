Common errors

Blocks and terms

“intro requires a dependent function goal.”
The next goal is not a function type. Inspect it; a pair needs witnesses, and an equality needs a path.
“Pair requires an expected type.”, “Sum injection requires an expected type.”
Supply a type with typed(T, (a, b)), a theorem signature, or a have block.
“Statements after exact are unreachable.”, “Statements after cases are not yet translated.”
A closing statement ends the block. Move further reasoning into the appropriate branch, or prove a local claim with have before finishing the outer block.
“Untyped lambda requires an expected function type.”
Give the binder a type, fun (x : A) => …, or put the lambda where a function type is expected.
“Type mismatch.”
The supplied term does not have the expected type by computation. Check argument order, universes, and dependent endpoints. From rfl, it means the sides are only propositionally equal: use a lemma, rw or simp. A propositional equality may require explicit transport.
“This computable declaration depends on non-computing assumptions: …”
The declaration, or a definition it uses, relies on an assumption. The error’s path names the definitions through which the first assumption enters. Replace that step with an assumption-free proof, or remove computable. See computability.
“The term evaluates to 6, not 7.”
An evaluate directive found a different normal form. The message shows both normal forms.
An attempted witness extraction from Mere(A) fails
Truncation elimination needs a proposition as its target. Proving mere existence does not in general supply a chosen witness.

Equational reasoning and simplification

“rw left an unresolved equality goal; add a following proof statement.”
The rewrite succeeded, but the new goal does not hold by conversion. Add another rw, an exact, or a simp. The same applies to the simp variants.
“Rewrite occurrence 3 was not found (1 eligible matches).”
Fewer matches exist than the requested occurrence. Check that the rule is instantiated with exactly the subterm that appears, and whether you meant at lhs or at rhs.
“Rewrite match occurs in an unsupported dependent position.”
The only match is under a binder or in a dependent argument. Use an explicit cong with a one-hole function.
“calc step left endpoint does not match the preceding endpoint.”, “calc final endpoint does not match the goal.”
Adjacent steps must share an endpoint up to conversion. Use _ to avoid retyping the previous right side.
“Simplification cycle detected in the selected rules.”
A rule, or a pair of rules, can rewrite a term back to an earlier state; commutativity always does. Instantiate the rule at specific arguments, or remove one direction.
“A simplification rule parameter is not determined by the matched side; supply arguments.”
Matching cannot fix every parameter. Pass the missing arguments explicitly, or use the rule in the other direction.
A conditional rule reports a blocked premise
No proof of the premise was found. List a local proof with simp with [h], or add a rule that proves the premise.
“… budget exceeded.”
Rewriting, matching, term size or elapsed work hit a fixed bound. Narrow the rule list with simp only, or split the proof with have or calc.
“path i => ... needs an expected Path or PathP type.”
Use the long form path(family, body), or place the shorthand where a path type is expected.

Not yet available

Rewriting currently supports homogeneous equality endpoints and type-valued goals through ordinary applications whose result type stays fixed. The following are not available yet:

  • rewriting a hypothesis together with everything that depends on it (simp at makes a new copy instead);
  • apply, refine and sorry;
  • general implicit or named arguments;
  • solving premises that are not equalities;
  • inequality and mixed-relation calc chains.
