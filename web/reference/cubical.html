Paths as functions of the interval

In cubical type theory, a path p : x = y in A is a function from an abstract interval into A. Its value at 0 is definitionally x and its value at 1 is y. Many path proofs can therefore be written directly, as functions of an interval coordinate, instead of by path induction. The operations of chapter 7, such as sym and trans, are built this way.

fun (i : Interval) => … binds a coordinate inside the forms below. Interval is not a type: it belongs to no universe and cannot be the domain of an ordinary function. A coordinate can be 0, 1, a bound coordinate i, or -i, the reversal 1 − i, also written flip(i). Two more operations, meets and joins, are described below.

FormMeaning
path(fun (i : Interval) => A, fun (i : Interval) => body)The path whose value at i is body, in the family A
path i => bodyThe same path, with the family read from the expected = or PathP type
at(p, i), or p @ iThe value of p at coordinate i. @ binds tighter than every infix operator except application.
PathP(fun (i : Interval) => A(i), a, b)The type of dependent paths from a : A(0) to b : A(1); see dependent paths. x = y is the case of a constant family.

Reversing a path is reading it backwards: its value at i is p’s value at -i. Written in full, and with the shorthand:

def reverse_path(A : U0, x, y : A, p : x = y) : y = x {
  exact path(fun (i : Interval) => A, fun (i : Interval) => at(p, flip(i)));
}

def reverse_again(A : U0, x, y : A, p : x = y) : y = x {
  exact path i => p @ -i;
}

def constant_path(A : U0, x : A) : x = x {
  exact path i => x;
}

def value_at_zero(A : U0, x, y : A, p : x = y) : p @ 0 = x {
  exact refl(x);
}

def value_at_one(A : U0, x, y : A, p : x = y) : p @ 1 = y {
  rfl;
}

reverse_again is the same term as reverse_path, with the family A read from the goal y = x. constant_path is refl(x). A path’s values at 0 and 1 are its endpoints by computation, which is how the kernel checks every endpoint:

def wrong_direction(A : U0, x, y : A, p : x = y) : x = y {
  // Error: Type mismatch: found p @ 1 = p @ 0, expected x = y.
  exact path i => p @ -i;
}

The shorthand needs an expected path type to supply the family:

// Error: path i => ... needs an expected Path or PathP type.
def no_expected_type(A : U0, x : A) := path i => x;

A coordinate is not a term, and Interval is not a type:

def coordinate_as_term(A : U0, x : A) : x = x {
  // Error: Interval coordinates can only be used in interval arguments.
  exact path i => typed(Nat, i);
}
def interval_as_type(i : Interval) := i;  // Error: Untranslated name: Interval

Squares

A path between paths is a function of two coordinates: a square. Its four sides are the paths at j = 0 and j = 1, and the paths traced by its corners. path j => path i => … writes one directly. The outer path j reads its family from the goal, and each inner path i from the equality that the goal’s family gives at j.

Given a pointwise equality H between two functions, applying f and g along a path p gives two paths, and H at the two ends joins them. They form a square:

def naturality_square(A, B : U0, f, g : A -> B,
    H : (forall a : A. f(a) = g(a)), x, y : A, p : x = y) :
  PathP(fun (j : Interval) => H(x) @ j = H(y) @ j, cong(f, p), cong(g, p)) {
  exact path j => path i => H(p @ i) @ j;
}

At j = 0, H(p @ i) @ 0 is f(p @ i), which traces cong(f, p); at j = 1, it traces cong(g, p). At i = 0 and i = 1 it traces H(x) and H(y). The goal is a PathP, a path over a family of equality types, because the type of the inner path changes with j; dependent paths describes them. The kernel checks all four sides.

Meets and joins

i & j is the smaller of two coordinates, their meet, and i | j the larger, their join; meet(i, j) and join(i, j) say the same. & binds tighter than |, and both tighter than @: p @ -i & j | k is p @ (((-i) & j) | k). The kernel inspector prints them as ∧ and ∨. At the corners of the square they are the familiar “and” and “or”:

iji & ji | j
0000
1001
0101
1111

A path applied to a meet or a join is a square, a function of two coordinates, called a connection. Squares like these are needed wherever one side of a square must shrink to a point. Along an edge, i & 0 is 0 and i & 1 is i, so p @ i & j is constant at x where j = 0 and is p where j = 1; p @ i | j is p where j = 0 and constant at y where j = 1. Both facts hold by computation:

def meet_edges(A : U0, x, y : A, p : x = y) :
  (refl(x) = (path i => p @ i & 0)) and (p = (path i => p @ i & 1)) {
  exact (refl(refl(x)), refl(p));
}

def join_edges(A : U0, x, y : A, p : x = y) :
  (p = (path i => p @ i | 0)) and (refl(y) = (path i => p @ i | 1)) {
  exact (refl(p), refl(refl(y)));
}

Read along the other coordinate, the meet shrinks p towards its start and the join shrinks it towards its end. In to_start, the square p @ i & j is refl(x) at j = 0 and p at j = 1; in to_end, p @ i | j is p at j = 0 and refl(y) at j = 1:

def to_start(A : U0, x, y : A, p : x = y) :
  PathP(fun (j : Interval) => x = p @ j, refl(x), p) {
  exact path j => path i => p @ i & j;
}

def to_end(A : U0, x, y : A, p : x = y) :
  PathP(fun (j : Interval) => p @ j = y, p, refl(y)) {
  exact path j => path i => p @ i | j;
}

The best-known use is the singleton of a point x: the type of pairs of an end y and a path x = y. It is contractible: it has a center, (x, refl(x)), and every element w is equal to it. The path from the center to w moves the end forward along w.2, and the meet grows the path along with it: at coordinate j the pair is the point w.2 @ j and the part of w.2 that reaches it, path i => w.2 @ i & j. At j = 0 that part is refl(x), and at j = 1 it is all of w.2. Read from j = 1 back to j = 0, the same path slides w back to the center, shrinking its path to refl(x).

def Singleton(A : U0, x : A) := exists y : A. x = y;

def singletons_contractible(A : U0, x : A) :
  exists center : Singleton(A, x). forall w : Singleton(A, x). center = w {
  exact (typed(Singleton(A, x), (x, refl(x))),
    fun (w : Singleton(A, x)) =>
      path j => (w.2 @ j, path i => w.2 @ i & j));
}

// Path induction, from paths: to prove C of every pair (y, p), prove it of
// the center and transport along the contraction.
def based_path_induction(A : U0, x : A, C : Singleton(A, x) -> U0,
    base : C((x, refl(x))), w : Singleton(A, x)) : C(w) {
  exact along C by singletons_contractible(A, x).2(w) from base;
}

based_path_induction is the reason this matters: a statement about every path starting at x follows from the single case refl(x). In cubical type theory path induction is derived in this way, not assumed: the built-in path_induction elaborates to a transport over the segments path j => p @ i & j, the same meet.

Picking the wrong one is caught at the edges. With a meet, the path at i runs from x to p @ i, not from p @ i to y:

def wrong_connection(A : U0, x, y : A, p : x = y) :
  PathP(fun (i : Interval) => p @ i = y, p, refl(y)) {
  // Error: Type mismatch: found p @ 0 = p @ i, expected p @ i = y.
  exact path i => path j => p @ j & i;
}

Coordinates obey the laws of a De Morgan algebra: & and | are associative, commutative and distribute over each other, and -(i & j) is -i | -j. They are not Boolean: i & -i is not 0, since at i = 1/2 it is 1/2. The checker does not simplify it away:

def not_boolean(A : U0, x, y : A, p : x = y) : refl(x) = (path i => p @ i & -i) {
  // Error: Type mismatch: found refl(x) = refl(x), expected refl(x) = (path i => p @ i & -i).
  exact refl(refl(x));
}

The composition tubes of hand-built proofs use connections in the same way. A tube fun (k : Interval) => q @ k & i is constant where i = 0 and follows q where i = 1, and fun (k : Interval) => p @ k | -i is constant where i = 0 and follows p where i = 1.

Dependent paths

A dependent function f : forall a : A. C(a) sends a path p : x = y to a path from f(x) to f(y), but these lie in different types, C(x) and C(y), so it is not an equality. It is a dependent path, a PathP over the family fun (i : Interval) => C(p @ i): at each coordinate its value lies in the type over p @ i. There are three ways to build one:

def section_path(A : U0, C : A -> U0, f : (forall a : A. C(a)), x, y : A, p : x = y) :
  PathP(fun (i : Interval) => C(p @ i), f(x), f(y)) {
  exact apd_path(f, p);
}

def section_by_hand(A : U0, C : A -> U0, f : (forall a : A. C(a)), x, y : A, p : x = y) :
  PathP(fun (i : Interval) => C(p @ i), f(x), f(y)) {
  exact path i => f(p @ i);
}

def section_via_transport(A : U0, C : A -> U0, f : (forall a : A. C(a)),
    x, y : A, p : x = y) :
  PathP(fun (i : Interval) => C(p @ i), f(x), f(y)) {
  over C along p by {
    exact apd(f, x, y, p);   // goal: transport(C, x, y, p, f(x)) = f(y)
  }
}

There are two standard ways to state that a dependent function respects a path. A PathP states it directly, as a path lying over p. The transported equality transport(C, x, y, p, f(x)) = f(y) states it in one fiber. apd_path produces the first and apd the second. over proves a PathP goal from the transported equality, when that is easier. The family C is never inferred: the elaborator does not search for a family that fits.

def not_a_path_goal(A : U0, C : A -> U0, x, y : A, p : x = y) : Nat {
  over C along p by {  // Error: over requires an expected PathP goal.
    exact 0;
  }
}

Function extensionality: ext

Two functions are equal when they agree at every input. For a goal f = g between functions, ext x; takes an input x and continues with the goal f(x) = g(x):

def pointwise_path(A, B : U0, f, g : A -> B, h : (forall x : A. f(x) = g(x))) : f = g {
  ext x;
  exact h(x);
}

def dependent_pointwise(A : U0, C : A -> U0, f, g : forall a : A. C(a),
    h : forall a : A. f(a) = g(a)) : f = g {
  ext a;
  exact h(a);
}

Cubical paths make function extensionality provable: path i => fun x => h(x) @ i is a path from f to g. ext x; builds that term. It works for dependent functions too, provided the goal is f = g with f, g : forall x : A. C(x). It uses no assumption; FunExt builds the same term. Unlike rw, ext never closes the block: a statement proving f(x) = g(x) must follow, even when that holds by rfl.

def not_functions(n : Nat) : n = n {
  ext x;  // Error: ext requires equality of functions.
  rfl;
}

Composition

comp(family, base, walls…) fills from coordinate 0 to coordinate 1, starting at base. Picture a square with the base as its bottom edge and the walls as its sides: comp produces the top edge. A wall face(i, 0, fun (j : Interval) => …) gives the side where the outer coordinate i is 0, and likewise for 1. The kernel checks that each wall starts on the base and that walls agree where they meet. With no walls, comp is transport.

def join(A : U0, x, y, z : A, p : x = y, q : y = z) : x = z {
  exact path i => comp(fun (j : Interval) => A, p @ i,
    face(i, 0, fun (j : Interval) => x),
    face(i, 1, fun (j : Interval) => q @ j));
}

def move(A : U0, C : A -> U0, x, y : A, p : x = y, v : C(x)) : C(y) {
  exact comp(fun (j : Interval) => C(p @ j), v);
}

join is how trans is built: the bottom edge is p, the left wall stays at x, and the right wall follows q. A wall that does not start on the base is rejected. Here the left wall starts at y, but the base starts at x:

def misplaced_wall(A : U0, x, y, z : A, p : x = y, q : y = z) : x = z {
  exact path i => comp(fun (j : Interval) => A, p @ i,
    face(i, 0, fun (j : Interval) => y),  // Error: Composition tube disagrees with its base.
    face(i, 1, fun (j : Interval) => q @ j));
}

fill(family, base, level, walls…) is the same filling stopped at the coordinate level, so it gives the whole square rather than its top edge. face_when(formula, wall) states a wall’s face as a formula built from on(i, 0), on(i, 1), and and or:

def filler(A : U0, x, y, z : A, p : x = y, q : y = z) :
  PathP(fun (j : Interval) => x = q @ j, p, trans(p, q)) {
  exact path j => path i => fill(fun (k : Interval) => A, p @ i, j,
    face(i, 0, fun (k : Interval) => x),
    face(i, 1, fun (k : Interval) => q @ k));
}

def join_by_formulas(A : U0, x, y, z : A, p : x = y, q : y = z) : x = z {
  exact path i => comp(fun (j : Interval) => A, p @ i,
    face_when(on(i, 0), fun (j : Interval) => x),
    face_when(on(i, 1), fun (j : Interval) => q @ j));
}

Interval and face formulas are kept in a normal form of joins of meets. Some compact formulas have exponentially large normal forms. Rather than exhaust memory, the checker refuses any expansion beyond 4,096 clauses or a fixed work budget, with a lattice budget error. Split such a proof into smaller named steps.

Higher inductive types

An inductive declaration can also include path constructors, which build paths rather than points. Write a path constructor’s endpoint equality as its result type:

inductive Circle : U0 {
  base;
  loop : base = base;
}

// For each coordinate i, loop @ i is a point of Circle.
def start : loop @ 0 = base { rfl; }
def finish : loop @ 1 = base { rfl; }

base is a point, and loop is a path from base to itself. A path is a function of an interval coordinate: for each i, loop @ i is a point of Circle, and its ends loop @ 0 and loop @ 1 are base. So Circle has two kinds of points: base, and the points loop @ i along the loop.

A function out of Circle is defined by match, with a clause for each kind of point. A clause is written as the point it covers: loop @ i => e gives the result at loop @ i. The matched value is that point, not the path. This function goes around the loop backwards:

inductive Circle : U0 {
  base;
  loop : base = base;
}

def reverse(c : Circle) : Circle := match c {
  base => base;
  loop @ i => loop @ -i;
};

def reverse_loop : cong(reverse, loop) = sym(loop) { rfl; }

At loop @ i, reverse returns loop @ -i, where -i is 1 − i. At i = 0 and i = 1 the point is base, so there the clause must agree with the base clause: loop @ -0 is loop @ 1, which is base, and loop @ -1 is loop @ 0, also base. Taken over all i, the clause traces a path between the results at base. Applying reverse along the whole loop, cong(reverse, loop), gives that path, sym(loop), and rfl checks this by computation.

A clause whose ends disagree with the point clause is rejected. Here the loop clause traces a path from 1 to 1, but the base clause requires one from 0 to 0:

inductive Circle : U0 {
  base;
  loop : base = base;
}

def broken(c : Circle) : Nat := match c {  // Error: Type mismatch: found 1 = 1, expected 0 = 0.
  base => 0;
  loop @ i => 1;
};

A constant clause traces the constant path. flatten sends every point of the loop to 0, so along the loop it gives refl(0). A path clause can also be omitted and its path proved instead: obligations by rfl proves the path the missing loop clause must give, 0 = 0.

inductive Circle : U0 {
  base;
  loop : base = base;
}

def flatten(c : Circle) : Nat := match c {
  base => 0;
  loop @ i => 0;
};

def flatten_loop : cong(flatten, loop) = refl(0) { rfl; }

def flatten_again(c : Circle) : Nat := match c {
  base => 0;
} obligations by rfl;

A header can also specify a truncation level. It adds a canonical constructor named TypeName.squash enforcing that level:

Header resultMeaning
: U0A type in U0, with no truncation imposed
: propA proposition: any two values are equal
: setA set: any two equality proofs with the same endpoints are equal
: trunc(n)A higher truncation level, for an integer n ≥ −1; prop is −1 and set is 0
: prop U1Both a truncation level and a universe
 
import hlevels;

inductive Mere(A : U0) : prop {
  point(value : A);
}

def same(A : U0, x, y : Mere(A)) : x = y := Mere.squash(x, y);

def discard(A : U0, x : Mere(A)) : Unit := match x {
  point(value) => tt;
};

A match on a truncated type must also respect its squash constructor. Importing hlevels lets the checker generate that branch when it can establish the required level of the result; Unit is a proposition in discard. Otherwise, write the squash clause, as the point it covers: Mere.squash(x, y) @ i => …, or give level evidence. Declared path clauses can be written in the match itself, or in a trailing obligations { … } block. Omitting a path clause requires a checked proof of its path, such as obligations by rfl above.

Pushouts

A pushout glues A and B along a span f : C -> A, g : C -> B. It is an ordinary declaration with a path constructor, in the pushout module:

inductive Pushout(U < UU0, V < UU0, W < UU0, C : U, A : V, B : W, f : C -> A, g : C -> B) : max(
  U, max(V, W)
) {
  inl(a : A);
  inr(b : B);
  push(c : C) : inl(f(c)) = inr(g(c));
}

After import pushout;, write its universe arguments explicitly, as for any declaration with universe parameters. The constructors take their instance from the expected type, and match eliminates a pushout: a clause for each side and a path clause push(c) @ i, which the kernel checks against the two side clauses at i = 0 and i = 1.

import pushout;

def TwoPoints : U0 := Pushout(U0, U0, U0, Nat, Unit, Unit, fun (n : Nat) => tt, fun (n : Nat) => tt);

def west : TwoPoints := inl(tt);

def east : TwoPoints := inr(tt);

def bridge(n : Nat) : west = east {
  exact push(n);
}

def collapse(value : TwoPoints) : Unit := match value {
  inl(a) => tt;
  inr(b) => tt;
  push(n) @ i => tt;
};

pushout_induction in the same module packages this elimination into a family over the pushout, with a dependent path over each push(c). Pushouts are not built into the kernel: they compose, transport and compute by the same rules as every declared higher inductive type.

Suspensions

The suspension of A is the pushout of the two maps A -> Unit. Its operations are ordinary definitions in the suspension library, so they are written with the pushout constructors:

import pushout;

def Suspension(A : U0) : U0 := Pushout(U0, U0, U0, A, Unit, Unit,
  fun (_ : A) => tt, fun (_ : A) => tt);
def north(A : U0) : Suspension(A) := inl(tt);
def south(A : U0) : Suspension(A) := inr(tt);
def meridian(A : U0, a : A) : north(A) = south(A) := push(a);

After import suspension_types;, Suspension(A) has the points north(A) and south(A) and, for every a : A, a path meridian(A, a) : north(A) = south(A). suspension_induction(A, C, atNorth, atSouth, coherence, point) eliminates into a family C over the suspension. The coherence case takes a : A and proves transport(C, north(A), south(A), meridian(A, a), atNorth) = atSouth.

import suspension_types;

def pole_path(A : U0, a : A) : north(A) = south(A) {
  exact meridian(A, a);
}

def to_unit(A : U0, point : Suspension(A)) : Unit {
  exact suspension_induction(A, fun (s : Suspension(A)) => Unit, tt, tt,
    fun (a : A) => refl(tt), point);
}

suspension_meridian_beta(A, C, atNorth, atSouth, coherence, a) is the computation law on a meridian, stated as an equality: the constructed section maps meridian(A, a) to coherence(a). The circle and puncture models build on these operations; see the suspension examples and the circle proof.
