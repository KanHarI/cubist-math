Paths as functions of the interval

In cubical type theory, a path p : x = y in A is a function from an abstract interval into A. Its value at 0 is definitionally x and its value at 1 is y. Many path proofs can therefore be written directly, as functions of an interval coordinate, instead of by path induction.

fun (i : Interval) => … binds a coordinate inside the forms below. Interval is not a type: it belongs to no universe and cannot be the domain of an ordinary function. A coordinate can be 0, 1, a bound coordinate i, flip(i) (the reversal 1 − i), meet(i, j) (minimum) or join(i, j) (maximum).

FormMeaning
path(fun (i : Interval) => A, fun (i : Interval) => body)The path whose value at i is body, in the family A
at(p, i), or p @ iThe value of p at coordinate i
PathP(fun (i : Interval) => A(i), a, b)The type of dependent paths from a : A(0) to b : A(1). x = y is the case of a constant family.
 
def reverse_path(A : U0, x y : A, p : x = y) : y = x {
  exact path(fun (i : Interval) => A, fun (i : Interval) => at(p, flip(i)));
}

def value_at_zero(A : U0, x y : A, p : x = y) : p @ 0 = x {
  exact refl(x);
}

def to_start(A : U0, x y : A, p : x = y) :
  PathP(fun (j : Interval) => x = p @ j, refl(x), p) {
  exact path j => path i => p @ meet(i, j);
}

value_at_zero holds by computation. In to_start, the square p @ meet(i, j) is refl(x) at j = 0 and p at j = 1. The kernel checks every endpoint:

def wrong_direction(A : U0, x y : A, p : x = y) : x = y {
  // Error: Type mismatch: found (at(p, 1) =[A] at(p, 0)), expected (x =[A] y).
  exact path i => p @ flip(i);
}

A coordinate is not a term, and Interval is not a type:

def coordinate_as_term(A : U0, x : A) : x = x {
  // Error: Interval coordinates can only be used in interval arguments.
  exact path i => typed(Nat, i);
}
def interval_as_type(i : Interval) = i;  // Error: Untranslated name: Interval

Shorthand

def reverse_again(A : U0, x y : A, p : x = y) : y = x {
  exact path i => p @ flip(i);
}

def constant_path(A : U0, x : A) : x = x {
  exact path i => x;
}

def naturality_square(A B : U0, f g : A -> B,
    H : (forall a : A, f(a) = g(a)), x y : A, p : x = y) :
  PathP(fun (j : Interval) => H(x) @ j = H(y) @ j, cong(f, p), cong(g, p)) {
  exact path j => path i => H(p @ i) @ j;
}

reverse_again is the same term as reverse_path, with the family read from the goal. naturality_square fills a square whose sides are cong(f, p), cong(g, p), H(x) and H(y). The outer path j gets its family from the PathP goal, and each inner path i from the equality at j. The kernel then checks all four edges.

The shorthand needs an expected path type to supply the family:

// Error: path i => ... needs an expected Path or PathP type.
def no_expected_type(A : U0, x : A) = path i => x;

Dependent paths

def section_path(A : U0, C : A -> U0, f : (forall a : A, C(a)), x y : A, p : x = y) :
  PathP(fun (i : Interval) => C(p @ i), f(x), f(y)) {
  exact apd_path(f, p);
}

def section_by_hand(A : U0, C : A -> U0, f : (forall a : A, C(a)), x y : A, p : x = y) :
  PathP(fun (i : Interval) => C(p @ i), f(x), f(y)) {
  exact path i => f(p @ i);
}

def section_via_transport(A : U0, C : A -> U0, f : (forall a : A, C(a)),
    x y : A, p : x = y) :
  PathP(fun (i : Interval) => C(p @ i), f(x), f(y)) {
  over C along p by {
    exact apd(f, x, y, p);   // goal: transport(C, x, y, p, f(x)) = f(y)
  }
}

There are two standard ways to state that a dependent function respects a path. A PathP states it directly, as a path lying over p. The transported equality transport(C, x, y, p, f(x)) = f(y) states it in one fiber. apd_path produces the first and apd the second. over proves a PathP goal from the transported equality, when that is easier. The family C is never inferred: the elaborator does not search for a family that fits.

def not_a_path_goal(A : U0, C : A -> U0, x y : A, p : x = y) : Nat {
  over C along p by {  // Error: over requires an expected PathP goal.
    exact 0;
  }
}

Function extensionality: ext

def pointwise_path(A B : U0, f g : A -> B, h : (forall x : A, f(x) = g(x))) : f = g {
  ext x;
  exact h(x);
}

def dependent_pointwise(A : U0, C : A -> U0, f g : forall a : A, C(a),
    h : forall a : A, f(a) = g(a)) : f = g {
  ext a;
  exact h(a);
}

Cubical paths make function extensionality provable: path i => fun x => h(x) @ i is a path from f to g. ext x; builds that term. It works for dependent functions too, provided the goal is f = g with f g : forall x : A, C(x). It uses no assumption; FunExt builds the same term. Unlike rw, ext never closes the block: a statement proving f(x) = g(x) must follow, even when that holds by rfl.

def not_functions(n : Nat) : n = n {
  ext x;  // Error: ext requires equality of functions.
  rfl;
}

Composition

comp(family, base, walls…) fills from coordinate 0 to coordinate 1, starting at base. Picture a square with the base as its bottom edge and the walls as its sides: comp produces the top edge. A wall face(i, 0, fun (j : Interval) => …) gives the side where the outer coordinate i is 0, and likewise for 1. The kernel checks that each wall starts on the base and that walls agree where they meet. With no walls, comp is transport.

def join(A : U0, x y z : A, p : x = y, q : y = z) : x = z {
  exact path i => comp(fun (j : Interval) => A, p @ i,
    face(i, 0, fun (j : Interval) => x),
    face(i, 1, fun (j : Interval) => q @ j));
}

def move(A : U0, C : A -> U0, x y : A, p : x = y, v : C(x)) : C(y) {
  exact comp(fun (j : Interval) => C(p @ j), v);
}

join is how trans is built: the bottom edge is p, the left wall stays at x, and the right wall follows q. A wall that does not start on the base is rejected. Here the left wall starts at y, but the base starts at x:

def misplaced_wall(A : U0, x y z : A, p : x = y, q : y = z) : x = z {
  exact path i => comp(fun (j : Interval) => A, p @ i,
    face(i, 0, fun (j : Interval) => y),  // Error: Composition tube disagrees with its base.
    face(i, 1, fun (j : Interval) => q @ j));
}

fill(family, base, level, walls…) is the same filling stopped at the coordinate level, so it gives the whole square rather than its top edge. face_when(formula, wall) states a wall’s face as a formula built from on(i, 0), on(i, 1), and and or:

def filler(A : U0, x y z : A, p : x = y, q : y = z) :
  PathP(fun (j : Interval) => x = q @ j, p, trans(p, q)) {
  exact path j => path i => fill(fun (k : Interval) => A, p @ i, j,
    face(i, 0, fun (k : Interval) => x),
    face(i, 1, fun (k : Interval) => q @ k));
}

def join_by_formulas(A : U0, x y z : A, p : x = y, q : y = z) : x = z {
  exact path i => comp(fun (j : Interval) => A, p @ i,
    face_when(on(i, 0), fun (j : Interval) => x),
    face_when(on(i, 1), fun (j : Interval) => q @ j));
}

Interval and face formulas are kept in a normal form of joins of meets. Some compact formulas have exponentially large normal forms. Rather than exhaust memory, the checker refuses any expansion beyond 4,096 clauses or a fixed work budget, with a lattice budget error. Split such a proof into smaller named steps.

Pushouts

Pushout(S, A, B, f, g), for f : S -> A and g : S -> B, glues A and B along S. Its constructors are push_left(P, a), push_right(P, b) and, for each s : S, the path push_path(P, s) : push_left(P, f(s)) = push_right(P, g(s)), where P is the pushout type.

def TwoPoints = Pushout(Nat, Unit, Unit, fun (n : Nat) => tt, fun (n : Nat) => tt);

def west = push_left(TwoPoints, tt);

def east = push_right(TwoPoints, tt);

def bridge(n : Nat) : west = east {
  exact push_path(TwoPoints, n);
}

def collapse(value : TwoPoints) : Unit {
  exact pushout_induction(fun (s : TwoPoints) => Unit,
    fun (a : Unit) => tt, fun (b : Unit) => tt, fun (n : Nat) => refl(tt), value);
}

pushout_induction(motive, leftCase, rightCase, bridgeCase, value) eliminates a pushout into a family over it. The bridge case gives, for each s, a path over push_path(P, s) between the two point cases. The constructor computations are checked by the kernel. Pushouts are built into the kernel today; user-declared higher inductive types are planned for stage 2 of the work plan.

Suspensions

The suspension of A is the pushout of the two maps A -> Unit. Its operations are ordinary definitions in the suspension library, so they are written with the pushout constructors:

def Suspension(A : U0) = Pushout(A, Unit, Unit,
  fun (_ : A) => tt, fun (_ : A) => tt);
def north(A : U0) = push_left(Suspension(A), tt);
def south(A : U0) = push_right(Suspension(A), tt);
def meridian(A : U0, a : A) = push_path(Suspension(A), a);

After import suspension_types;, Suspension(A) has the points north(A) and south(A) and, for every a : A, a path meridian(A, a) : north(A) = south(A). suspension_induction(A, C, atNorth, atSouth, coherence, point) eliminates into a family C over the suspension. The coherence case takes a : A and proves transport(C, north(A), south(A), meridian(A, a), atNorth) = atSouth.

import suspension_types;

def pole_path(A : U0, a : A) : north(A) = south(A) {
  exact meridian(A, a);
}

def to_unit(A : U0, point : Suspension(A)) : Unit {
  exact suspension_induction(A, fun (s : Suspension(A)) => Unit, tt, tt,
    fun (a : A) => refl(tt), point);
}

suspension_meridian_beta(A, C, atNorth, atSouth, coherence, a) is the computation law on a meridian, stated as an equality: the constructed section maps meridian(A, a) to coherence(a). The circle and puncture models build on these operations; see the suspension examples and the circle proof.
