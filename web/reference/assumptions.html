Axioms and propositional truncation

The operations in this section use explicit universe-specialized axiom schemas. They are explicit dependencies, not consequences of the basic introduction and elimination rules. A source file cannot add assumptions of its own: axiom declarations are rejected, as described in declarations.

Truncation

Truncate(U0, A), often named Mere(A) by the library, expresses mere inhabitation. It discards access to a chosen witness. The inspector can render it as ‖A‖; that is display notation, not source syntax.

Small-universe operationMeaning
Truncate(U0, A)The propositional truncation of A : U0.
TruncateIntro(U0, A, a)Send a : A into its truncation.
TruncateProp(U0, A)Evidence that any two elements of the truncation are equal.
TruncateElim(U0, A, P, proposition, map)Given proposition : forall x : P, forall y : P, x = y and map : A -> P, return Truncate(U0, A) -> P.

For a named universe, use Truncate(U, A), TruncateIntro(U, A, a), TruncateProp(U, A), or TruncateElim(U, A, P, proposition, map). Here U must be a universe such as U1, and both A and the elimination target P must belong to it.

The current library truncation constructor returns a type in U₀ even for larger inputs. These wrappers preserve that signature; they do not assert universe-preserving truncation. In particular, Truncate(U1, U0) is valid, while Truncate(U0, U0) is not.

Function extensionality and univalence

Pointwise equal functions can be proved equal without an axiom using ext. The FunExt interface below remains for existing proofs that were written against it. It is an assumption and is recorded as one.

FunExt(U0, A, B, f, g, pointwise)
For a family B : A -> U0 and dependent functions f, g, turn forall x : A, f(x) = g(x) into f = g.
FunExt(U, A, B, f, g, pointwise)
The explicit-universe form, with A : U and B : A -> U.
Univalence(U0, A, B)
The single axiom: IsEquiv(U1, (A =[U0] B), Equiv(U0, A, B), idtoequiv(U0, A, B)).
idtoequiv(U, A, B, p)
The equivalence induced by a type equality, constructed by path induction without axioms.
ua(U0, A, B, equivalence)
For small types and equivalence evidence in the library’s native equivalence representation, produce A = B. A pair of arbitrary forward and backward maps is not enough.
UnivalenceBeta(U0, A, B, equivalence, x)
Prove that transport of x : A along the univalence path equals the image of x under the equivalence’s forward function.

ua(U)(A, B, e) is the inverse extracted from Univalence(U, A, B). UnivalenceBeta is a derived transport theorem. UnivalenceEta(U, A, B, p) proves ua(U, A, B, idtoequiv(U, A, B, p)) = p. Neither law is an additional axiom. All accept a parameter U : Universe.

Classical principles and choice

LEM(U0, A, doubleNegation)
Uses excluded middle to turn doubleNegation : (A -> Void) -> Void into Truncate(U0, A), for A : U0.
Choice(U)(A, B, setA, setFibers, inhabited)
For A : U, B : A -> U, and inhabited : forall a : A, Truncate(U, B(a)), obtain Truncate(U, forall a : A, B(a)). setA proves that A is a set; setFibers proves it for every fiber. This applies the existing choice axiom at the selected universe. It does not return a selected function outside truncation.

All these interfaces are first-class universe specializations: Choice(U0), FunExt(U1), Truncate(U2) and Univalence(U1) are functions you can name or pass onward. A declared U : Universe also works. Supplying the universe and later arguments together is equivalent: Choice(U0, A, B, setA, setFibers, inhabited).

Universe parameters are specialized by the elaborator before kernel checking. For example, Choice(U0) selects the choice schema at U0; the kernel sees a named context assumption with that specialized signature. There is no kernel application of a generic Choice term to U0. Applying this specialized assumption to A, B, and its remaining arguments does produce ordinary kernel applications. The inspector and workbench show the generic schema, the universe substitution, and the checked instance separately. The generic schema display is explanatory notation, not a checked kernel term.

These are separate dependencies: using truncation or function extensionality does not by itself request excluded middle or choice. Inspect the axiom list on the particular theorem for the dependencies of its checked derivation, including its type and context.

Computability

Every assumption in the previous section is a name with a type and no computation rule. A term that uses one can stop computing. LEM(U0, A, doubleNegation) has type Truncate(U0, A), but it is not built from any element of A, so nothing can be computed from it. A term that uses no assumption is built from the kernel’s own rules only. The kernel is designed so that such a closed term reduces to a canonical value: a closed Nat reduces to a numeral. The test suite checks this on closed examples. The language lets a declaration require it, and lets a file test what a term computes to.

computable def

Writing computable before def or opaque def requires the declaration to use no assumption. The checker collects the assumptions of the checked term, of its type and of every definition they mention. This is the same list that the inspector shows. If the list is not empty, the declaration is rejected. The error names every assumption, and one chain of definitions through which the first one enters. A rejected declaration is not added, so the declarations that use it are blocked too.

import primes;

computable def double(n : Nat) = n + n;

computable def double_two : double(2) = 4 {
  rfl;
}

A computable declaration may take parameters, like double. The requirement is about assumptions, not about closed terms: every application of double to a numeral computes. The library’s double_negation is proved with excluded middle, so a declaration that uses it cannot be computable:

import classical;

computable def recover(P : U0, prop : Proposition(P), nn : (P -> Void) -> Void) : P {
  exact double_negation(P, prop, nn);
}

The error reads: This computable declaration depends on non-computing assumptions: LEM(U0), Truncate(U0), TruncateElim(U0). Path to LEM(U0): double_negation (classical) → LEM(U0). Without the modifier, the same proof is accepted and its assumptions are listed as usual. The modifier changes nothing else: a computable declaration is checked and unfolded like any other.

evaluate

evaluate term expecting value; is a top-level directive, placed between declarations. It checks both terms and requires term to use no assumption. It requires the two to have the same type, then compares their normal forms. It defines no name. A success is reported with the normal form. A failure is an error that makes the module incomplete, so every evaluation is rechecked with the rest of its module.

import primes;

def double(n : Nat) = n + n;

evaluate double(3) expecting 6;
evaluate double(double(1)) expecting 2 + 2;
import primes;

def double(n : Nat) = n + n;

evaluate double(3) expecting 7;

The expected side is normalized too, so it may be any term of the same type. Writing a literal makes the directive state what the term computes to. Evaluation computes full normal forms: it unfolds opaque definitions and ignores with unfolding hints. computable, evaluate and expecting are keywords only in these positions. Elsewhere they are ordinary names.

The command-line checker prints each success as evaluate at line N: value. After check, its evaluate EXPRESSION command prints the normal form of an expression in the scope of the checked module, under the same rule. inspect NAME lists the declaration’s assumptions, or none. See checking and inspection.

Truncation is itself an assumption in the current kernel, so a term of type Truncate(U0, A) never evaluates. The kernel roadmap makes truncation an inductive type with a computation rule. After that, a closed truncated term that uses no other assumption will compute, and evaluate is planned to read the witness inside it.
