The library assumptions

A few principles are assumed rather than constructed. Each is a name with a type and no computation rule, provided by the checker at a chosen universe. There are six. A source file cannot add more: there is no axiom declaration, and a hypothesis is taken as a parameter instead, as described in declarations.

AssumptionType, at U0
Truncate(U0, A)The propositional truncation of A : U0, a type in U0
TruncateIntro(U0, A, a)Sends a : A into Truncate(U0, A)
TruncateProp(U0, A, x, y)Any two elements x y of the truncation are equal
TruncateElim(U0, A, P, proposition, map, t)Given proposition : forall x y : P, x = y and map : A -> P, maps t : Truncate(U0, A) to P
LEM(U0, A, doubleNegation)Excluded middle: from (A -> Void) -> Void, an element of Truncate(U0, A)
Choice(U0, A, B, setA, setFibers, inhabited)The axiom of choice for a set A and a family of sets B: from inhabited : forall a : A, Truncate(U0, B(a)), an element of Truncate(U0, forall a : A, B(a))

Truncate(U0, A), which the library often names Mere(A), says that A is inhabited without giving access to a chosen element. The inspector displays it as ‖A‖; that is display notation, not source syntax.

def merely(A : U0, a : A) : Truncate(U0, A) {
  exact TruncateIntro(U0, A, a);
}

def all_equal(A : U0, x y : Truncate(U0, A)) : x = y {
  exact TruncateProp(U0, A, x, y);
}

def into_a_proposition(A P : U0, proposition : forall x : P, forall y : P, x = y,
    map : A -> P, t : Truncate(U0, A)) : P {
  exact TruncateElim(U0, A, P, proposition, map, t);
}
import sets;

def excluded_middle(A : U0, nn : (A -> Void) -> Void) : Truncate(U0, A) {
  exact LEM(U0, A, nn);
}

def choose(A : U0, B : A -> U0, setA : IsSet(A), setB : forall a : A, IsSet(B(a)),
    inhabited : forall a : A, Truncate(U0, B(a))) : Truncate(U0, forall a : A, B(a)) {
  exact Choice(U0, A, B, setA, setB, inhabited);
}

The inspector lists every assumption a theorem uses, computed from its checked term, type and the definitions they mention. The assumptions are independent: using truncation does not by itself request excluded middle or choice.

Universes

The first argument chooses the universe. Truncate(U1, A) truncates a type A : U1, and U : Universe parameters work too. The universe and the later arguments can be supplied separately: Choice(U0) and Truncate(U2) are functions that can be named and passed on.

def truncate_at_two := Truncate(U2);

def choice_at_zero := Choice(U0);

def truncate_types := Truncate(U1, U0);

def generic(U : Universe, A : U) := Truncate(U, A);

The checker specializes each assumption to its universe before kernel checking: the kernel sees a named context assumption with the specialized type, such as LEM(U0). The inspector shows the generic schema, the universe and the checked instance separately.

Truncation returns a type in U0 even for larger inputs. Thus Truncate(U1, U0) is valid, but Truncate(U0, U0) is not, because U0 is not a type in U0.

def too_large := Truncate(U0, U0);  // Error: Type mismatch: found U1, expected U0.
// Error: Logical assumptions require a concrete universe and an explicit native context.
def no_universe(A : U0) := Truncate(A);
// Error: Too many arguments to TruncateIntro.
def extra_argument(A : U0, a : A) := TruncateIntro(U0, A, a, a);

Extensionality and univalence compute

Function extensionality and univalence are not assumptions. In cubical type theory both are constructions, and the checker builds them from the kernel’s own rules:

FunExt(U, A, B, f, g, pointwise)
For B : A -> U, dependent functions f and g, and pointwise : forall x : A, f(x) = g(x), the path f = g. It builds the same term as ext, which is usually shorter.
ua(U, A, B, equivalence)
A path A = B from an equivalence equivalence : Equiv(U, A, B), defined by import paths;. An equivalence is a function with an inverse, two homotopies and the triangle law; a pair of maps is not enough.
UnivalenceBeta(U, A, B, equivalence, x)
Transport of x : A along ua(U, A, B, equivalence) equals the image of x under the equivalence.

All three need every argument; there is no separate univalence axiom. Because they use no assumption, results built on them can be marked computable, and transport along ua computes:

import paths;

def swap(p : Unit and Nat) := unpack p as (u, n) return Nat and Unit { typed(Nat and Unit, (n, u)); };

def swap_back(p : Nat and Unit) := unpack p as (n, u) return Unit and Nat { typed(Unit and Nat, (u, n)); };

computable def swap_equivalence : Equiv(U0, Unit and Nat, Nat and Unit) {
  exact (swap, swap_back, fun (p : Unit and Nat) => refl(p), fun (q : Nat and Unit) => refl(q),
    fun (p : Unit and Nat) => refl(refl(swap(p))));
}

computable def swapped : (Unit and Nat) = (Nat and Unit) {
  exact ua(U0, Unit and Nat, Nat and Unit, swap_equivalence);
}

evaluate along (fun (T : U0) => T) by swapped from typed(Unit and Nat, (tt, 3))
  expecting typed(Nat and Unit, (3, tt));
computable def extensional(A : U0, B : A -> U0, f g : forall a : A, B(a),
    h : forall a : A, f(a) = g(a)) : f = g {
  exact FunExt(U0, A, B, f, g, h);
}

Computability

A term that uses an assumption can stop computing. LEM(U0, A, doubleNegation) has type Truncate(U0, A), but it is not built from any element of A, so nothing can be computed from it. A term that uses no assumption is built from the kernel’s own rules only. The kernel is designed so that such a closed term reduces to a canonical value: a closed Nat reduces to a numeral. The test suite checks this on closed examples. The language lets a declaration require it, and lets a file test what a term computes to.

computable def

Writing computable before def or opaque def requires the declaration to use no assumption. The checker collects the assumptions of the checked term, of its type and of every definition they mention; this is the same list that the inspector shows. If the list is not empty, the declaration is rejected. The error names every assumption, and one chain of definitions through which the first one enters. A rejected declaration is not added, so the declarations that use it are blocked too.

import naturals;

computable def double(n : Nat) := n + n;

computable def double_two : double(2) = 4 {
  rfl;
}

A computable declaration may take parameters, like double. The requirement is about assumptions, not about closed terms: every application of double to a numeral computes. The library’s double_negation is proved with excluded middle, so a declaration that uses it cannot be computable:

import classical;

computable def recover(P : U0, prop : Proposition(P), nn : (P -> Void) -> Void) : P {
  // Error: This computable declaration depends on non-computing assumptions:
  //   LEM(U0), Truncate(U0), TruncateElim(U0).
  //   Path to LEM(U0): double_negation (classical) → LEM(U0).
  exact double_negation(P, prop, nn);
}

The error lists every assumption the proof uses, and the chain of definitions through which the first one enters: here the library’s double_negation. When the assumption is used directly, the chain is just its name:

computable def merely(A : U0, a : A) : Truncate(U0, A) {
  // Error: This computable declaration depends on non-computing assumptions:
  //   Truncate(U0), TruncateIntro(U0). Path to Truncate(U0): Truncate(U0).
  exact TruncateIntro(U0, A, a);
}

Without the modifier, the same proofs are accepted and their assumptions are listed as usual. The modifier changes nothing else: a computable declaration is checked and unfolded like any other.

evaluate

evaluate term expecting value; is a top-level directive, placed between declarations. It checks both terms and requires term to use no assumption. It requires the two to have the same type, then compares their normal forms. It defines no name. A success is reported with the normal form. A failure is an error that makes the module incomplete, so every evaluation is rechecked with the rest of its module.

import naturals;

def double(n : Nat) := n + n;

evaluate double(3) expecting 6;
evaluate double(double(1)) expecting 2 + 2;
import naturals;

def double(n : Nat) := n + n;

evaluate double(3) expecting 7;  // Error: The term evaluates to 6, not 7.
// Error: The evaluated term depends on non-computing assumptions: Truncate(U0), TruncateIntro(U0).
//   Path to Truncate(U0): Truncate(U0).
evaluate TruncateIntro(U0, Nat, 3) expecting TruncateIntro(U0, Nat, 3);

The expected side is normalized too, so it may be any term of the same type. Writing a literal makes the directive state what the term computes to. Evaluation computes full normal forms: it unfolds opaque definitions and ignores with unfolding hints. computable, evaluate and expecting are keywords only in these positions. Elsewhere they are ordinary names.

The command-line checker prints each success as evaluate at line N: value. After check, its evaluate EXPRESSION command prints the normal form of an expression in the scope of the checked module, under the same rule. inspect NAME lists the declaration’s assumptions, or none. See checking and inspection.

Truncation is itself an assumption in the current kernel, so a term of type Truncate(U0, A) never evaluates. The kernel roadmap makes truncation an inductive type with a computation rule. After that, a closed truncated term that uses no other assumption will compute, and evaluate is planned to read the witness inside it.
