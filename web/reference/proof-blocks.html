Proof blocks

A proof block builds a term one statement at a time. Each statement extends the context, changes the goal, or closes it.

Goals and statements

A proof block is the body of a block declaration: def name(params) : T { … }. It starts with the goal T and a context holding the parameters. Each statement does one of three things:

  • it extends the context and continues with the same goal: let, have, obtain;
  • it changes the goal and continues with the new one: intro, rw, simp, ext;
  • it closes the goal and ends the block: exact, cases, rfl, calc, simpa, over.
def swap_product(A B : U0) : (A and B) -> (B and A) {
  intro pair;            // goal: B and A
  obtain (a, b) := pair;  // context: a : A, b : B
  let saved := a;
  have result : B and A {
    exact (b, saved);
  }
  exact result;          // closes the goal
}

A block must end by closing its goal. A block that runs out of statements first is rejected:

def unfinished(A : U0) : A -> A {
  intro a;  // Error: Proof block has no conclusion.
}

Nothing may follow a closing statement in the same block:

def after_the_end(A : U0, a : A) : A {
  exact a;
  exact a;  // Error: Statements after exact are unreachable.
}

An unknown word where a statement belongs is a syntax error:

def not_a_statement(a : Nat) : Nat {
  return a;  // Error: Expected a proof statement; found 'return'.
}

intro

intro x; takes the next input of a function goal. For a goal forall x : A, B(x), it adds x : A to the context and leaves B(x). For an implication P -> Q, it adds a proof of P and leaves Q. intro x y h; is three introductions in a row; the inspector shows the context after each one.

def curry(A B C : U0) : ((A and B) -> C) -> A -> B -> C {
  intro f a b;
  exact f((a, b));
}

The goal’s type is computed first, so intro works on a named definition that unfolds to a function type:

def Endo(A : U0) := A -> A;

def compose_endo(A : U0, f g : Endo(A)) : Endo(A) {
  intro a;
  exact f(g(a));
}

A goal that is not a function type has nothing to introduce. This includes asking for more names than the goal has inputs:

def nothing_to_introduce : Nat {
  intro n;  // Error: intro requires a dependent function goal.
  exact n;
}
def one_input_only(A : U0) : A -> A {
  intro a b;  // Error: intro requires a dependent function goal.
  exact a;
}

A function goal can also be closed without intro, by giving the function: exact fun (a : A) => a;.

The name after intro is chosen by the author. Its spelling does not determine its type; the goal does. Here setA gets the type IsSet(A) because that is the next input of the goal:

import sets;

def SetAssumption := forall A : U0, IsSet(A) -> IsSet(A);

def use_set_assumption : SetAssumption {
  intro A;       // A : U0, from the forall
  intro setA;    // setA : IsSet(A), from the implication
  exact setA;
}

exact

exact term; checks the term against the goal and closes the block. The two types need only be equal by computation, as described in conversion:

import naturals;

def by_computation : 2 + 2 = 4 {
  exact refl(4);
}

def identity_function(A : U0) : A -> A {
  exact fun (a : A) => a;
}
def wrong_type(A B : U0, a : A) : B {
  exact a;  // Error: Type mismatch: found A, expected B.
}

have

have proves a local claim and adds it to the context. It has three forms:

FormUse
have name : T { … }Prove T in a nested block. The block sees the surrounding context.
have name : T := term;Check term against T. Shorthand for have name : T { exact term; }. The := keeps an = inside T unambiguous.
have name := term;Name a term whose type the elaborator can infer.
 
def three_ways(n : Nat) : n = n {
  have p := refl(n);
  have q : n = n := p;
  have r : n = n {
    exact q;
  }
  exact r;
}

def from_context(A B : U0, a : A, b : B) : A and B {
  have pair : A and B {
    exact (a, b);
  }
  exact pair;
}

Use have to split a long argument into named steps, and to state an equality whose endpoints the elaborator cannot infer. Without a type, have name := term; gives the term no expected type, so a pair is rejected:

def untyped_pair(a b : Nat) : Nat and Nat {
  have p := (a, b);  // Error: Pair requires an expected type.
  exact p;
}

The nested block of have must close its own goal:

def empty_claim(a : Nat) : Nat {
  have b : Nat {  // Error: Proof block has no conclusion.
  }
  exact b;
}

let

let name := term; names a term for the rest of the block. The name stands for the term itself, so the checker sees through it: refl(m) below proves succ(n) = succ(n) because m is succ(n). To give the term an expected type, write let name := typed(T, term);.

def see_through(n : Nat) : succ(n) = succ(n) {
  let m := succ(n);
  exact refl(m);
}

def with_type(n : Nat) : Nat and Nat {
  let pair := typed(Nat and Nat, (n, n));
  exact pair;
}

let names one term. To take a pair apart, use obtain:

def pattern_in_let(p : Nat and Nat) : Nat {
  let (a, b) = p;  // Error: Use obtain to unpack a pair.
  exact a;
}

obtain

obtain (a, b) := pair; names the components of a pair or dependent pair. Patterns can be tuples and can nest, following the shape of the type.

def witness(t : exists n : Nat, (n = n) and Unit) : Nat {
  obtain (n, same, u) := t;
  exact n;
}

def inner_unit(t : (Nat and Unit) and Nat) : Unit {
  obtain ((a, u), b) := t;
  exact u;
}

Like let, obtain introduces no new variables. Each name stands for a component of the pair, so (n, q) is equal to p by computation. A goal that mentions the original pair therefore still works:

def about_the_pair(P : (exists n : Nat, n = n) -> U0,
    h : forall n : Nat, forall q : n = n, P((n, q)), p : exists n : Nat, n = n) : P(p) {
  obtain (n, q) := p;
  exact h(n, q);
}

The pattern must match the type’s shape, and a pattern needs at least two components:

def not_a_pair(n : Nat) : Nat {
  obtain (a, b) := n;  // Error: obtain requires a dependent pair matching its pattern.
  exact a;
}
def too_many_components(p : Nat and Nat) : Nat {
  obtain (a, b, c) := p;  // Error: obtain requires a dependent pair matching its pattern.
  exact a;
}
def one_component(p : Nat and Nat) : Nat {
  obtain (a) := p;  // Error: A pair pattern needs at least two components.
  exact a;
}

obtain does not open a propositional truncation: a merely existing witness cannot be named.

cases

cases value { left x => { … } right y => { … } } proves the goal once for each side of a sum. Each branch is a block with the side’s component in its context. cases closes the goal.

def swap_sum(A B : U0, value : A or B) : B or A {
  cases value {
    left a => { exact right(a); }
    right b => { exact left(b); }
  }
}

def reassociate(A B C : U0, value : A or (B or C)) : (A or B) or C {
  cases value {
    left a => { exact left(left(a)); }
    right rest => {
      cases rest {
        left b => { exact left(right(b)); }
        right c => { exact right(c); }
      }
    }
  }
}
def not_a_sum(n : Nat) : Nat {
  cases n {  // Error: cases requires a sum type.
    left a => { exact 0; }
    right b => { exact 1; }
  }
}

cases must be the last statement of its block:

def after_cases(value : Unit or Unit) : Unit {
  cases value {
    left a => { exact a; }
    right b => { exact b; }
  }
  exact tt;  // Error: Statements after cases are not yet translated.
}

cases does not change the goal in each branch. If the goal mentions value, both branches still see value, not left(x) or right(y), and a branch that needs the refined goal fails:

def Shape(value : Unit or Unit) := match value as z return U0 {
  left a => Nat;
  right b => Unit;
};

def default(value : Unit or Unit) : Shape(value) {
  cases value {
    // Error: Type mismatch: found Unit -> Nat, expected Unit -> Shape(value).
    left a => { exact 0; }
    right b => { exact tt; }
  }
}

For such a goal, use a dependent match, which substitutes each side into the result type:

def Shape(value : Unit or Unit) := match value as z return U0 {
  left a => Nat;
  right b => Unit;
};

def default(value : Unit or Unit) : Shape(value) {
  exact match value as z return Shape(z) {
    left a => 0;
    right b => tt;
  };
}

Changing the goal

rw, simp and ext replace the goal with a new one and continue. Some of them finish the block when the new goal holds by computation; the chapters on rewriting and function extensionality say when. Otherwise, a following statement proves the new goal.

import naturals;

def rewrite_then_finish(n : Nat) : (n + 0) + 0 = n {
  rw [nat_add_zero(n)];
  exact nat_add_zero(n);
}

def pointwise(A B : U0, f : A -> B) : f = fun (x : A) => f(x) {
  ext x;
  rfl;
}

In rewrite_then_finish, rw turns the goal into n + 0 = n, which exact then proves. In pointwise, ext x turns the goal into f(x) = f(x), which still needs rfl:

def pointwise(A B : U0, f : A -> B) : f = fun (x : A) => f(x) {
  ext x;  // Error: Proof block has no conclusion.
}

Where blocks can appear

A block can appear as the body of a block declaration, of have, of each cases branch, of a calc step, and of over. A block is not an expression: to use a proof inside a term, prove it first with have, or move it into its own declaration.

def block_as_term : Nat and Nat {
  exact ({ exact 0; }, 1);  // Error: Expected an expression, found '{'.
}
