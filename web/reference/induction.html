Natural numbers are an ordinary source inductive, which the standard prelude imports from nat. Declared types are checked by H1, on by default since its release.

Declaring an inductive type

An inductive declaration introduces a type and the constructors that build its values. This type has two constructors, each taking no arguments:

inductive Bool : U0 {
  false;
  true;
}

def enabled : Bool := true;

Bool : U0 says that Bool is a small type. Each constructor ends with ;; the declaration ends with }. A constructor without a written result builds the declared type. Constructor arguments go in parentheses, with their types. A recursive argument can itself have the declared type.

For example, the standard nat module contains this entire declaration:

inductive Nat : U0 {
  zero;
  succ(n : Nat);
}

zero : Nat builds zero, and succ(n) builds the successor of n : Nat. Decimal numerals abbreviate these constructors: 2 is succ(succ(zero)). Nat, zero and succ are ordinary imported names. They are available through the standard prelude; an explicit import nat; also works. In the proof workspace, click Nat and choose View source to open its declaration.

You can put your own inductive declaration in a module and import it like a def. Declarations become available in source order. If you omit the universe after :, the checker chooses the least universe containing the constructor data and recursive argument domains. An explicit universe must be large enough for them. See universes for the level notation.

Parameters and constructors

A type can take parameters. Here U ranges over finite universes, and A : U is the type of the elements stored in the list:

inductive List(U < UU0, A : U) : U {
  nil;
  cons(head : A, tail : List(U, A));
}

def empty : List(U0, Nat) := nil;
def numbers : List(U0, Nat) := cons(2, cons(3, nil));
def empty_again := typed(List(U0, Nat), nil);

List(U0, Nat) is a type. nil builds an empty list, and cons(head, tail) prepends an element. Write the universe and type arguments when applying List. The constructors take only their declared arguments; their instance is inferred from the expected type. A result annotation, a function argument type, or typed can supply it. In numbers, the expected type also reaches the nested constructors.

inductive List(U < UU0, A : U) : U {
  nil;
  cons(head : A, tail : List(U, A));
}

def ambiguous := nil;  // Error: nil needs an expected type, to know which List(…) it builds: write typed(List(…), nil).

A recursive occurrence uses the declaration's own parameters, as List(U, A) does in tail. Indices that change these arguments, mutually recursive declarations, and negative occurrences such as List(U, A) -> A as a constructor argument are not supported. A recursive argument may also be a function into the declared type, as in node(children : Nat -> Tree); a structural call then takes a child children(n).

Functions by pattern matching

Use match to define what a function does at each constructor. Give the result type in the function header or with return on the match:

inductive Bool : U0 {
  false;
  true;
}

def negate(value : Bool) : Bool := match value {
  false => true;
  true => false;
};

def negates_true : negate(true) = false { rfl; }

def predecessor(n : Nat) := match n return Nat {
  zero => zero;
  succ(k) => k;
};

def predecessor_three : predecessor(3) = 2 { rfl; }

Each branch names a constructor and binds its arguments in their declared order. In succ(k), k is the predecessor, a value of type Nat. Branches are expressions ending in ;. Supply one branch for every point constructor; missing, duplicate, or unknown constructors are rejected.

Matching a constructor computes to its branch. Thus negate(true) computes to false and predecessor(3) to 2; rfl checks both equalities by computation. Matching an unknown variable waits until its constructor is known.

Structural recursion

A definition can call itself on a recursive child bound by its match. The arithmetic library defines addition this way:

def add(x, y : Nat) : Nat := match x {
    zero => y;
    succ(k) => succ(add(k, y));
  };

For zero, return y. For succ(k), recursively add k and y, then take the successor. The recursive call uses the smaller child k. The same rule works on your own inductive types:

inductive List(U < UU0, A : U) : U {
  nil;
  cons(head : A, tail : List(U, A));
}

def length(U < UU0, A : U, xs : List(U, A)) : Nat := match xs {
  nil => 0;
  cons(head, tail) => succ(length(U, A, tail));
};

def numbers : List(U0, Nat) := cons(2, cons(3, nil));
def length_two : length(U0, Nat, numbers) = 2 { rfl; }

Give a recursive definition a result type. Its body must be a match on one of its parameters, either a match expression or a match in a proof block. A recursive call passes a child for that parameter. Universe parameters and parameters on which the matched type depends stay the same: length keeps U and A. Other arguments can change, which allows an accumulator:

def count_into(n, total : Nat) : Nat := match n {
  zero => total;
  succ(k) => count_into(k, succ(total));
};

def counted : count_into(2, 3) = 5 { rfl; }

A call on the original input or on a newly constructed value does not satisfy the structural rule:

def growing(n : Nat) : Nat := match n {
  zero => 0;
  // Error: The recursive call of growing is not on an argument of the matched constructor: only structural recursion, as growing(m) in succ(m) => ….
  succ(k) => growing(succ(k));
};

These calls are checked as structural eliminations; arbitrary recursive equations are not admitted. The computation of a recursive definition at a constructor follows its written branch, so concrete results can be proved with rfl.

Proofs and dependent results

A proof about an inductive value is a function whose result type can depend on that value. In a proof block, match specializes the goal to each constructor, and each branch contains a proof block:

import naturals;

def add_zero(n : Nat) : n + 0 = n {
  match n {
    zero => { rfl; }
    succ(k) => { exact cong(succ, add_zero(k)); }
  }
}

The zero branch proves 0 + 0 = 0 by computation. The successor branch needs succ(k) + 0 = succ(k), which computes to succ(k + 0) = succ(k). The recursive proof add_zero(k) has type k + 0 = k; applying cong(succ, …) gives the required proof. Here k is the predecessor, and add_zero(k) supplies the induction hypothesis.

A match expression can state its dependent result explicitly. Bind the matched value with as and write the family after return:

import naturals;

def add_zero(n : Nat) : n + 0 = n :=
  match n as value return value + 0 = value {
    zero => refl(0);
    succ(k) => cong(succ, add_zero(k));
  };

In match n as value return C(value), the zero branch produces C(zero) and the successor branch produces C(succ(k)). The family C is called the motive. Write it over the name bound by as, so each branch gets its own instance. This also works for dependent functions on lists and other declared types. A proof-block match reads the motive from the goal and closes that goal in every branch.

Paths and truncation

An inductive declaration can also include path constructors. Write their endpoint equality as the constructor's result type:

inductive Circle : U0 {
  base;
  loop : base = base;
}

// For each coordinate i, loop @ i is a point of Circle.
def start : loop @ 0 = base { rfl; }
def finish : loop @ 1 = base { rfl; }

base is a point, and loop is a path from base to itself. A path is a function of an interval coordinate: for each i, loop @ i is a point of Circle, and its ends loop @ 0 and loop @ 1 are base. So Circle has two kinds of points: base, and the points loop @ i along the loop. See cubical paths for coordinates and @.

A function out of Circle gives a clause for each kind of point. A clause is written as the point it covers: loop @ i => e gives the result at loop @ i. The matched value is that point, not the path. This function goes around the loop backwards:

inductive Circle : U0 {
  base;
  loop : base = base;
}

def reverse(c : Circle) : Circle := match c {
  base => base;
  loop @ i => loop @ -i;
};

def reverse_loop : cong(reverse, loop) = sym(loop) { rfl; }

At loop @ i, reverse returns loop @ -i, where -i is 1 − i. At i = 0 and i = 1 the point is base, so there the clause must agree with the base clause: loop @ -0 is loop @ 1, which is base, and loop @ -1 is loop @ 0, also base. Taken over all i, the clause traces a path between the results at base. Applying reverse along the whole loop, cong(reverse, loop), gives that path, sym(loop), and rfl checks this by computation.

A clause whose ends disagree with the point clause is rejected. Here the loop clause traces a path from 1 to 1, but the base clause requires one from 0 to 0:

inductive Circle : U0 {
  base;
  loop : base = base;
}

def broken(c : Circle) : Nat := match c {  // Error: Type mismatch: found 1 = 1, expected 0 = 0.
  base => 0;
  loop @ i => 1;
};

A constant clause traces the constant path. flatten sends every point of the loop to 0, so along the loop it gives refl(0). A path clause can also be omitted and its path proved instead: obligations by rfl proves the path the missing loop clause must give, 0 = 0.

inductive Circle : U0 {
  base;
  loop : base = base;
}

def flatten(c : Circle) : Nat := match c {
  base => 0;
  loop @ i => 0;
};

def flatten_loop : cong(flatten, loop) = refl(0) { rfl; }

def flatten_again(c : Circle) : Nat := match c {
  base => 0;
} obligations by rfl;

A header can also specify a truncation level. It adds a canonical constructor named TypeName.squash enforcing that level:

Header resultMeaning
: U0A type in U0, with no truncation imposed
: propA proposition: any two values are equal
: setA set: any two equality proofs with the same endpoints are equal
: trunc(n)A higher truncation level, for an integer n ≥ −1; prop is −1 and set is 0
: prop U1Both a truncation level and a universe
 
import hlevels;

inductive Mere(A : U0) : prop {
  point(value : A);
}

def same(A : U0, x, y : Mere(A)) : x = y := Mere.squash(x, y);

def discard(A : U0, x : Mere(A)) : Unit := match x {
  point(value) => tt;
};

A match on a truncated type must also respect its squash constructor. Importing hlevels lets the checker generate that branch when it can establish the required level of the result; Unit is a proposition in discard. Otherwise, write the squash clause, as the point it covers: Mere.squash(x, y) @ i => …, or give level evidence. Declared path clauses can be written in the match itself, or in a trailing obligations { … } block. Omitting a path clause requires a checked proof of its path, such as obligations by rfl above.

Natural-number induction

The existing induction notation also works on the imported Nat. It uses the same declared type and its generic eliminator. Unlike a recursive match, its successor branch binds the recursive result directly:

def copy(n : Nat) := induction n return Nat {
  zero => 0;
  succ previous => succ(previous);
};

def copy_two : copy(2) = 2 {
  exact refl(2);
}

The zero branch gives the result for 0. In the successor branch, previous is the result for the predecessor, and the branch gives the result for its successor. Each branch is an expression, not a proof block; put a longer argument in a separate helper theorem.

When the result type depends on the number, or the successor branch uses the predecessor, name the number with as. In induction n as k return C(k), the zero branch must have type C(0). In the successor branch, k : Nat is the predecessor and previous : C(k) is the induction hypothesis. The branch must produce C(succ(k)). Without as, as in copy, every branch has the one type after return, and the predecessor is unnamed. An as name that neither the return type nor the successor branch uses draws a warning:

def copy(n : Nat) := induction n as k return Nat {  // Warning: k is unused: the return type does not mention it and the successor clause does not use it.
  zero => 0;
  succ previous => succ(previous);
};

The motive C(k) is what makes this a proof by induction rather than just recursion. For a theorem, it is the statement at k. For example, the library proves n + 0 = n with the motive (k + 0) = k:

def nat_add_zero(x : Nat) := induction x as k return ((k + 0) = k) {
    zero => refl(0);
    succ h => cong((fun (n : Nat) => succ(n)), h);
  };

The zero branch needs 0 + 0 = 0, which holds by computation. The successor branch has h : k + 0 = k and needs succ(k) + 0 = succ(k). That computes to succ(k + 0) = succ(k), which is cong of succ applied to h. When a statement quantifies over further variables, put them inside the motive, as in return (forall y : Nat, …), so the induction hypothesis is general enough.

Why the motive is not written over x. x is one fixed number, the input of nat_add_zero. A return type that mentions x states one fact about that number, the same in every branch. Without as, the zero branch would have to prove x + 0 = x rather than 0 + 0 = 0, which refl(0) does not prove. The hypothesis h would also be x + 0 = x, the theorem itself, not the statement for the predecessor:

import naturals;

def nat_add_zero(x : Nat) := induction x return ((x + 0) = x) {  // Error: Type mismatch: found 0 = 0, expected x + 0 = x.
    zero => refl(0);
    succ h => cong((fun (n : Nat) => succ(n)), h);
  };

as k introduces a new name for the number that varies from branch to branch. The motive (k + 0) = k is then a family: 0 + 0 = 0 at zero, and succ(k) + 0 = succ(k) at a successor, with h : k + 0 = k. The new name may repeat the input's: in induction x as x return ((x + 0) = x), the motive's x is the varying one. A recursive match states the theorem once in the header, add_zero(n : Nat) : n + 0 = n, and specializes it to each constructor for you.

The order on natural numbers

The arithmetic library defines <= by induction on its first argument, with the motive Nat -> U0. For each x, the induction builds a function that takes y and returns the type x <= y: Unit when it holds and Void when it does not. < is defined from it.

// Order, computed: 0 <= b is Unit; succ(a) <= 0 is Void;
// succ(a) <= succ(b) is a <= b.
def le(x : Nat) := induction x return (Nat -> U0) {
    zero => (fun (x2 : Nat) => Unit);
    succ h => (fun (y : Nat) => match y return U0 {
        zero => Void;
        succ(j) => h(j);
      });
  };

// Strict order: n < p is succ(n) <= p.
def isLt(n, p : Nat) := le(succ(n), p);

0 <= y is Unit for every y. For succ(k) <= y, a match looks at y. succ(k) <= 0 is Void, and succ(k) <= succ(j) is h(j), where h is the function built for the predecessor k, so it is k <= j. A comparison of numerals therefore computes all the way to Unit or Void, and tt proves a true one.

The induction needs no as: its motive Nat -> U0 is the same for every number, and its successor branch uses only h. The inner case analysis needs the predecessor j of y but no recursive result, so it is a match, whose clause succ(j) names the predecessor where it is used.

With a variable, the computation stops at the variable, and a proof goes by induction:

import naturals;

// 0 <= n computes to Unit.
def zero_le(n : Nat) : 0 <= n {
  exact tt;
}

// n <= succ(n), by induction on n.
def le_succ(n : Nat) := induction n as k return (k <= succ(k)) {
  zero => tt;
  succ h => h;
};

In le_succ, the zero branch needs 0 <= 1, which is Unit. The successor branch has h : k <= succ(k) and needs succ(k) <= succ(succ(k)), which computes to k <= succ(k): exactly h. The library proves n <= n the same way, as nat_le_refl, and so n < succ(n), which computes to n <= n.

Binary numbers

Unary Nat is simple to reason about, but n takes n constructors. The archive's binary_naturals module declares binary numbers, which take one constructor per digit:

inductive BinaryPositive : U0 {
  binary_one;
  binary_bit0(p : BinaryPositive);
  binary_bit1(p : BinaryPositive);
}

// Zero is separate, so every nonzero numeral ends at the one leaf.
inductive BinaryNat : U0 {
  binary_zero;
  binary_positive(p : BinaryPositive);
}

A positive number is its leading binary_one with its other digits appended, the last digit outermost: binary_bit0(p) is 2p and binary_bit1(p) is 2p + 1. Zero is a constructor of its own, so no number has a leading zero and each has one representation. Functions on binary numbers use match and structural recursion, like functions on Nat:

import binary_naturals;
import naturals;

def positive_value(p : BinaryPositive) : Nat := match p {
  binary_one => 1;
  binary_bit0(q) => 2 * positive_value(q);
  binary_bit1(q) => succ(2 * positive_value(q));
};

def value(n : BinaryNat) : Nat := match n {
  binary_zero => 0;
  binary_positive(p) => positive_value(p);
};

def six : value(0b110) = 6 { rfl; }

After import binary_naturals;, a literal such as 0b110 has type BinaryNat and expands to binary_positive(binary_bit0(binary_bit1(binary_one))). 0b0 expands to binary_zero. Leading zeroes do not affect the value. Only digits 0 and 1 are accepted; the parser permits at most 256 significant bits, and the kernel's term-depth resource bound also applies. Digits are stored as text, so there is no machine-number rounding. These literals denote nonnegative numbers; decimal literals still use unary Nat.

binary_add, binary_mul and binary_of_nat are available from binary_arithmetic. Arithmetic symbols are not overloaded. The binary factorial proof and base-2 and base-10 instances compute 10! without a unary expansion of 3628800.
