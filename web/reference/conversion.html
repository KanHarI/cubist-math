Equality by computation

The checker accepts a term when its type is definitionally equal to the requested type. Two terms are definitionally equal when they reduce to the same normal form. refl and rfl prove an equality exactly when its sides are definitionally equal. The reduction steps are:

  • beta: a function applied to an argument computes, so (fun (n : Nat) => succ(n))(0) is 1;
  • delta: a named definition unfolds to its checked body;
  • eliminator rules: induction, match, unpack and the other eliminators compute on constructors, so 2 + 2 is 4 but n + 0 is stuck on the variable n;
  • eta: a function equals fun x => f(x), and a pair equals the pair of its components;
  • cubical rules: a path at 0 or 1 is its endpoint, and interval formulas are compared in normal form.
import primes;

def beta : (fun (n : Nat) => succ(n))(0) = 1 {
  rfl;
}

def double(n : Nat) = succ(succ(n));

def delta : double(1) = 3 {
  rfl;
}

def eliminators : match typed(Unit or Nat, right(4)) return Nat { left u => 0; right n => n; } = 2 + 2 {
  rfl;
}
def function_eta(A B : U0, f : A -> B) : f = fun (x : A) => f(x) {
  rfl;
}

def pair_eta(p : Nat and Nat) :
  p = unpack p as (a, b) return Nat and Nat { typed(Nat and Nat, (a, b)); } {
  rfl;
}

def path_endpoint(A : U0, x y : A, p : x = y) : p @ 1 = y {
  rfl;
}

An eliminator applied to a variable does not compute, so an equality that needs a case analysis or induction on the variable is not definitional. It is a theorem, proved with a lemma, rw or simp:

import primes;

def plus_zero(n : Nat) : n + 0 = n {
  rfl;  // Error: Type mismatch: found (add(n, 0) =[Nat] add(n, 0)), expected (add(n, 0) =[Nat] n).
}

The checker never uses a theorem automatically. A proved equality such as commutativity is a path, not a reduction rule; rw and simp use it only when it is named in the proof or registered with simp_rule.

Opaque definitions

opaque def is accepted syntax. It is currently checked and unfolded exactly like def: conversion opens boxed_successor(1) to succ(1), which is the numeral 2. There is no separate operation that unfolds a term on request; conversion unfolds definitions as it needs them.

opaque def boxed_successor(n : Nat) = succ(n);

def opened_is_two : boxed_successor(1) = 2 {
  exact refl(2);
}

def opened_in_a_type(v : boxed_successor(0) = 1) : 1 = 1 {
  exact v;
}

Unfolding hints

with unfolding [name₁, name₂] { expression } scopes conversion hints around one expression. The list names already checked definitions; the braces hold one expression, without a trailing semicolon. Empty lists and nested scopes are allowed.

def identity(n : Nat) = n;

def identity_zero : identity(0) = 0 {
  exact with unfolding [identity] { refl(0) };
}

def twice(n : Nat) = identity(identity(n));

def nested : twice(0) = 0 {
  exact with unfolding [twice] { with unfolding [identity] { refl(0) } };
}

def no_hints : 0 = 0 {
  exact with unfolding [] { refl(0) };
}

The checker first tries unfolding the listed definitions while keeping others folded; ordinary conversion remains available. The hints apply only inside the braces. The compiler may keep the result as a checked helper definition, so the enclosing proof can reuse it without expanding it again. Rechecking that helper replays its hints; they do not leak into the surrounding expression. Hints change the order of reduction, never the type, the assumptions or the proof obligations. They are guidance for performance, not evidence of an equality, and they do not normalize the whole expression. evaluate ignores them.

def unknown_hint : 0 = 0 {
  // Error: No checked definition to unfold: missing_name
  exact with unfolding [missing_name] { refl(0) };
}

Only top-level definitions can be listed; a parameter or local name is not one:

def local_hint(n : Nat) : n = n {
  exact with unfolding [n] { refl(n) };  // Error: No checked definition to unfold: n
}
def identity(n : Nat) = n;

def statement_in_braces : identity(0) = 0 {
  exact with unfolding [identity] { refl(0); };  // Error: Expected '}', found ';'.
}
