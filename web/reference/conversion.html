Conversion and opacity

The checker accepts a term when its type is definitionally equal to the requested type. Two terms are definitionally equal when they reduce to the same normal form by these steps:

  • beta: a function applied to an argument computes, so (fun (n : Nat) => succ(n))(0) is 1;
  • delta: a named definition unfolds to its checked body;
  • eliminator rules: induction, match, unpack and similar forms compute on constructors, so 2 + 2 is 4 but n + 0 is stuck on the variable n;
  • eta: a function equals fun x => f(x), and a pair equals the pair of its projections;
  • cubical rules: a path at 0 or 1 is its endpoint, and interval formulas are compared in normal form.

This is why refl and rfl prove some equalities and not others. They succeed exactly when both sides reach the same normal form.

def defines both constructions and proofs. The checker retains named definitions and can unfold their checked bodies to establish equality of types. opaque def is accepted syntax, but currently has the same checking and unfolding behavior as def. Proof blocks appear by name in the inspector, where their bodies can be opened.

opaque def boxed_successor(n : Nat) = succ(n);

def opened_is_two : boxed_successor(1) = 2 {
  exact refl(2);
}

Conversion opens boxed_successor(1) to succ(1), which is the numeral 2, so refl(2) checks. There is no separate operation that unfolds a term on request: conversion unfolds definitions as it needs them. A theorem such as commutativity is still a propositional equality. The checker never uses a theorem automatically as a rewrite rule. rw and simp use theorems only when they are named in the proof or registered with simp_rule.

In the native cubical backend, with unfolding [name₁, name₂] { expression } scopes selective conversion hints around an expression. The bracketed list contains names of already checked definitions; the braces contain one expression, without a trailing semicolon. Empty lists and nested scopes are allowed. For example:

def identity(n : Nat) = n;
def identity_zero : identity(0) = 0 {
  exact with unfolding [identity] { refl(0) };
}

The checker first tries unfolding the selected wrappers while keeping other definitions folded; ordinary conversion remains available. During elaboration, the hints apply only inside the braces. The compiler may retain the result as a checked helper definition, so the enclosing proof can reuse it without re-expanding it. Rechecking that helper replays its selected strategy; the hints do not leak into surrounding expressions. Hints change reduction order, never the type, assumptions, or proof obligations. They are performance guidance, not evidence of an equality, and do not normalize the whole expression.
